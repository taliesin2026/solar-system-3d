# 太阳系 3D 模拟器

真实轨道计算 + 自转 / 公转 / 卫星系统的交互式 3D 模拟。纯前端，双击 `index.html` 即可运行，无需联网、无需服务器。

## 在线预览

**▶ 立即体验：https://taliesin2026.github.io/solar-system-3d/**

由 GitHub Pages 托管，与仓库 `main` 分支同步，每次推送后自动重新部署。

```
solar-system/
├── index.html      # 全部逻辑（单文件，5548 行）
├── lib/
│   ├── three.min.js        # r147
│   └── OrbitControls.js    # 已打帧率无关阻尼补丁
├── verify.js       # 纯 Node 验证脚本（214 项断言，不碰 GPU）
├── palette.js      # 离线配色/对比度模型（复现 ACES 链，从 index.html 读配置）
└── README.md
```

## 运行

直接双击 `index.html`，或用任意静态服务器：

```bash
python3 -m http.server 8000   # 然后打开 http://127.0.0.1:8000
```

（写这条命令前确认过：这台机器上只有 `python3`，`python` 不存在——照旧文档敲 `python -m http.server` 会得到 `command not found`，而 `?nogl=1` 那一节又明确要求必须走 http，`file://` 会把查询串剥掉。）

依赖已本地化到 `lib/`，断网也能用。页面**不发出任何网络请求**：没有 fetch/XHR/ES module/跨域图片，13 张星球贴图全部由 Canvas 程序化生成，两个库都是 classic script。

首次加载有 1–5 秒纯计算时间（生成纹理），期间由 `#boot` 启动层显示转圈与文案。任何失败路径都会把这一层**改写成错误面板**，而不是留下"面板齐全 + 画面全黑 + 列表空 + 所有按钮是死的"（那曾经是最坏的一种故障形态——控制台之外零提示）：

| 情况 | 面板文案 |
|---|---|
| 脚本报异常 | 启动失败：脚本出错，界面已停止响应（附 message + 文件:行号） |
| `lib/three.min.js` 缺失 | 三维库未能加载（附"请保持整个文件夹完整"的说明） |
| 浏览器禁用 JS | `<noscript>` 全屏提示 |

## 操作

### 鼠标 / 触屏

| 操作 | 默认模式 | 平移模式（`Ctrl+Tab` 或「✥ 平移」） |
|---|---|---|
| 左键拖拽 | 旋转视角 | **平移** |
| 中键拖拽 | 旋转视角 | 旋转 |
| 右键拖拽 | 平移 | 平移 |
| 滚轮 | 缩放（指针须落在画面上） | 同左 |
| 双指捏合 | 缩放（触屏） | 同左 |
| 悬浮天体 | 标签高亮 + 悬浮详情卡 + 手型光标 | 同左 |
| 点击天体 | 聚焦并跟随 | 同左 |
| 点击空白处 | 解除跟随 | 同左 |

平移模式借的是 CAD 的习惯：不单靠右键，而是"模式开关 + 左键当前工具"，单手也能平移。实现上没有改库——OrbitControls r147 的 `onMouseDown` 读的就是 `scope.mouseButtons.{LEFT,MIDDLE,RIGHT}`，换映射即可。中键原本是 `DOLLY`（推拉），但滚轮缩放已被自定义 handler 独占（`enableZoom = false`），中键空着正好拿来旋转。

按钮下方 `#mouseHint` 那一行会随模式改写当前语义，这是画面上**唯一**说明"此刻左键干什么"的地方，矮窗口下只压行高、不隐藏。

| 键 | 作用 |
|---|---|
| `空格` | 暂停 / 继续时间推进 |
| `R` | 重置视角（回默认机位、清除选中、缩放回到自动） |
| `F` | 全览（水星→冥王星整个入画） |
| `← ↑ → ↓` | 平移画面 |

| `Esc` | 解除跟随；面板开着时关闭面板 |
| `?` | 打开 / 关闭「操作与快捷键」面板 |

焦点落在可交互控件（`input`/`select`/`textarea`、带 `role` 的按钮与开关）上时，全局快捷键**全部让路**：滑块上的方向键仍调滑块、日期框里的方向键仍切年/月/日、复选框上的空格仍勾选。裸 `Tab` 曾经被抢去做平移模式切换（还 `preventDefault`），结果键盘完全走不进界面，现在平移模式改用 `Ctrl+Tab`。

### 三栏怎么分

按**功能相似度**分区（用户反馈"界面有点无序、天体列表要靠拖动才看全"）：左栏是"怎么摆怎么画"（操作），右栏是"选谁、它怎么样"（数据），底栏是"画面上叠不叠这一层"（开关 + 读数）。

三栏各带一个 `─` 最小化按钮，收起后只剩标题条（字形换成 `+`），画面立刻宽出一整栏。这条链路必须四件事同时成立，少一件就是"点了没反应"：① 按钮 id 真的被 JS `getElementById` 接线（`#mLeft`/`#mRight`/`#mBottom`）；② 点下去切的是面板上的 `.min` 类，CSS 里 `#left.min,#right.min{max-height:none}`；③ `aria-expanded` 与 `aria-label`/`title` 一起改写（读屏与悬浮提示都说得清当前是收起还是展开）；④ **收起之后要重测底栏高度 `--bh`**——底栏收起时它自己变矮，左右栏的 `max-height:calc(100vh - var(--bh))` 不重测就仍然按旧高度让位，白留一条空隙。键盘 `Enter` 与 `Space` 等价（`role=button` 的默认约定）。用户第 1 条报的"点了无效"就是 ① 整条缺失：三个按钮当时是纯装饰，见「踩过的坑」第 23 条。

### 左栏 · 操作

- **时间** —— `⏸ 暂停` / `今天` / `◀ 逆转`；时间流速滑块（默认 `1.00 小时/秒`，即 1 秒 = 1 小时；范围 `0.3 分钟/秒` → `365 天/秒`）；跳转日期（`<input type=date>`，`min=1800-01-01` `max=2050-12-31`）
- **视角控制** —— 观察距离滑块（对数）+ `自动` / `全览`（同一行）；`俯视` `侧视` `跟随` `✥ 平移` **一行四等分**，下一行独占 `↺ 重置视角`，再下面是左右键语义提示 `#mouseHint`。四方向箭头「方向盘」已按用户要求**整体删掉**（`.padgrid` / `.vcol` / `.pad[data-dx]` 都不在 markup 里了）：平移留着三条入口——`✥` 模式开关（左键拖拽）、右键拖拽、系统方向键；中心 `✥` 原来那句"取消跟随 + 视线移回太阳"由 `重置视角(R)` 与 `Esc` 覆盖。省下的 5 格 × 26px 换成一行按钮 + 一行提示，视角段矮了两行
- **显示尺度** —— `真实距离` / `对数压缩`（摆放口径）、星球大小滑块（×1 → ×20000，**默认 ×1 = 1:1 真实比例，不放大**）、`真实星球大小`、`月球真实距离`。这四个旋钮本来就是同一件事（画多大 / 摆多远），原先散在两个面板里才叫无序；`id` 与 `class` 全部保持原样，JS 绑定一行都没改
- **脚注** `#note` —— 比例口径说明，常驻不滚走

三段都是自然高度的固定段，**左栏没有伸缩段**。

### 右栏 · 数据

- **信息卡** `#info` —— 选中天体的读数，宽屏常驻；`≤900px` 变成抽屉，右上角 `ℹ 详情` 唤出、抽屉顶部 `✕` 关闭
- **天体列表** —— 30 项按 7 个分类分组，是右栏唯一的伸缩段（`.sec.grow#secBodies` → `#plistWrap` 容器内部滚动）。**常驻只有 11 个主天体**（两列格子），19 颗行星卫星收在「⁘ 行星卫星」分组里默认折叠（三列格子，容器是 `.satfold`），点标题（或键盘 `Enter`/`空格`）展开；从画面里直接点卫星会自动展开并滚进视野。列表放在右栏是因为这里宽与高都更充裕——左栏要挤三组控件，30 项塞进去只能拖滚动条才看全

### 底栏

- **画面叠加层**（6 个开关，固定 **3 列 × 2 行** grid）—— 轨道线、常显全部标签、月球与卫星、黄道参考网格、星空背景、行星自转。「真实星球大小 / 月球真实距离」两个开关已并入左栏的「显示尺度」，底栏因此只剩"画面上要不要叠这一层"，薄了一大截。固定列数而不是 `flex-wrap`：8 个开关按可用宽度折成 3+3+2 时最后一行永远缺几个，右边参差；grid 的行数是算出来的，不随文案长度漂。格子等宽的前提是标签必须短：「（联动真实大小）」这类长尾巴放在 `title`、`?` 面板和本 README 里，开关本身仍会把「真实星球大小」一起点亮（看得见），切换时状态条也会播报
- **HUD** —— 日期、流速、`⏸`、`?`；流速过快时亮起「自转显示已限速」
- 底栏实际高度由 `ResizeObserver` 量出来写进 `--bh`，左右栏的 `max-height` 和 `#status` 的 `bottom` 都读这个变量——底栏换行变两倍高时，面板会跟着让位

### 窄屏

`≤900px` 时天体信息卡默认收起，右上角出现 `ℹ 详情` 按钮唤出、抽屉顶部 `✕` 关闭（宽屏由 CSS 隐藏这两个按钮）。旧写法在窄屏直接 `display:none` 整块信息卡，而触屏设备恰恰最需要"点一下看详情"。

`#bInfo` 的基础规则 `display:none` **必须写在 `@media(max-width:900px)` 之前**——它曾经写在后面，于是窄屏的 `display:inline-flex` 永远压不过它，详情按钮在所有宽度下都是死的，CSS 一个字都没报错。

## 读数口径

同一件事在不同界面必须给同一个数。这一版把所有读数收敛到一处实现。

**轨道速度** = 当前时刻的真实速度，用中心数值微分：

```js
h = 0.02 天
v = |P(t+h) − P(t−h)| / (2h)      // 场景单位 → km/s 用 AU_KM/86400 换算
```

悬浮详情卡与右侧信息面板**共用 `planetSpeedKms()`**。旧悬浮卡写死的是**近日点**速度 `29.7847·a^(-1/2)·√((1+e)/(1−e))`，整条轨道上是常数——水星在远日点仍写 58.98 km/s（真实约 39，高估 52%），而同一时刻面板写 52.36，一张卡内口径打架。

**日心距离**：每个天体都存一份与显示映射无关的真实 AU（`b.trueAU`），标签、悬浮卡、信息面板都读它。旧写法 `场景坐标长度 ÷ (real?100:1)` 在 `real` 下是对的，在**对数压缩**下把场景单位直接标成 AU，于是同一屏里对错混着显示：`金星1817.17 AU / 火星2051.63 AU / 木星2407.05 AU`（真实 0.72 / 1.52 / 5.2）。

**月球给两个距离**：地心距（千 km）与日心距（AU）分开标。旧写法是 `helio = 1 + 地心距`——实测五个日期恒等于 1+地心。真实月球日心距会在 0.997–1.003 之间**跨过 1 AU**（月球能跑到地球背日一侧），同时还被抹掉了地球自身 0.983–1.017 的变化；一个"永远 ≥1.0024 且与地心距同增同减"的数根本不是日心距。

**行星卫星**：显示「到母星 X 万 km」而不是 AU（数量级太小，AU 读数会全是 0.0000），另外附日心距与公转周期（海卫一标"逆"）。

**直径**：`直径（平均）` 为主行，扁的行星另给 `赤道 …km`。表里存的是平均半径，而四大行星常被引用的却是赤道直径（木星 139,822 vs 142,984、土星 116,464 vs 120,536，差 2–3%），只写一个"直径"，用户拿任何一本教材对照都会以为显示错了。

**转轴倾角**：统一是**对黄道面**的值。月球过去写「6.68°」——那是它对**自身轨道面**的最大夹角，同表口径不一致，且渲染出的月轴垂直黄道、与卡片数字对不上。现在给 `tilt:1.54`（对黄道，Cassini 定律），附注「对黄道面 1.54°（对自身轨道面 6.68°）」，并真的给月球建了 `axis` 组施加倾角。

**1800–2050 之外**：`min`/`max` 属性拦不住直接键入和粘贴。越界时**仍按根数外推**（否则按钮看起来像坏了），但日期框标红、状态条明确警告：

> ⚠ 1700 年在轨道根数适用范围（1800–2050）之外：结果是对 JPL 近似表的线性外推，误差随年份增长，不可当作真值

非法日期（空、格式错、2 月 30 日这类不存在的日子）则拒绝写入并回弹到当前值。

## 数据源与精度

| 内容 | 来源 |
|---|---|
| 行星位置 | JPL SSD 近似轨道根数表（1800–2050，J2000 平黄道）：9 行星 × 6 根数 + 6 个世纪速率 |
| 月球位置 | Jean Meeus《Astronomical Algorithms》第 47 章，ELP2000-82 截断级数 |
| 卫星轨道与半径 | NASA 行星事实页 / 各卫星条目，19 条 |
| 反照率 | NASA/JPL **几何**反照率（不是 Bond 反照率——几何反照率按定义就是零相位角时反射回观察者的光比，正是肉眼看到的屏幕观感） |
| 物理常数 | 平均半径、赤道半径、恒星自转周期、转轴倾角 |

解算链：

```
L = L₀ + L̇·T   →   M = L − ϖ   →   牛顿迭代解 E − e·sinE = M
  →  ν, r  →  旋转到黄道系 (x,y,z)  →  eclToThree(x,y,z) = (x, z, −y)
```

`T = (JD − J2000)/36525`（儒略世纪）。近日点幅角 `ω = ϖ − Ω` 与平近点角 `M = L − ϖ` 是两个不同的量，别混。角速率（`aDot`/`LDot` 等）单位统一为**度/儒略世纪**。黄道面映射为 XZ 平面，+Y 指向北黄极。

已核对项：

- 9 行星 × 6 根数 = **54 个数值**与 JPL 表逐条一致。其中海王星近日点经度原写 `44.96476227`，表值是 `44.97137259`——Δϖ̄ = −0.0066° 带来约 5×10⁵ km 的横向系统误差，基本吃掉了下面那张残差表声称的量级。已改回表值（速率 −0.32241464/世纪本来就对）。
- Meeus 表 47.A 有一行被误抄成 `(2,1,1,0): Σl=294`，而 `(2,1,1,0)` 在上面已以 `Σl=−810` 出现过——同一行不可能有两个系数。原表是 `(2,0,3,0): Σl=294`。幅度 294 μdeg ≈ 2 km，可忽略，但修掉之后"按 Meeus Ch.47 实现"这句话才成立。其余 Σb、A1/A2/A3、L/D/M/M′/F 多项式、E 因子、385000.56 km 常数逐条无误。
- **地球速度随历元变化**：近日点 30.29、远日点 29.29，当前 29.85，与 `vis-viva` 独立复核差 2.6e-3。
- 月球日心距在一年内**两侧跨过 1 AU**（>1 有 6 次、<1 有 6 次），摆动幅度 ≈ 2× 月地距离；且满足三角不等式 |月球日心距 − 地球日心距| ≤ 月地距离。
- 月地距离区间 357k–407k km（Meeus 截断表允许 ±2%）；黄纬落在黄白交角 ±5.145° 带内。
- 开普勒方程牛顿迭代残差 < 1e-13°。
- 自转轴：每颗行星 `axis` 与黄道法线的夹角 = 表列倾角（9/9 吻合，用 `transformDirection` 量世界方向），天王星确实"躺平"（axis·ŷ = −0.135）。地球公转方向与俯视自洽（从 +Y 看逆时针）。
- 逆行自转只由**倾角 > 90°** 判定（`isRetro = d => d.tilt > 90`），周期恒为正，界面显示 `Math.abs(rot)` + `(逆)`。数据表原来同时写了 `tilt:177.36` 和 `rot:−243.025`，自转又叠加在已经翻倒的轴上——负负得正，实测金星自转角速度方向 ω·ẑ = **+0.997**，渲染成和地球同向顺行（天王星、冥王星同理）。
- 地球自转相位做了历元对齐（`earthSpinDeg`）：由日心黄经得太阳黄经、叠加 UT 日分数求时角再投影到赤道面。旧写法 `jd*360/rot` 是**无历元依据的绝对相位**，跳到"2026-10-07 12:00"时北京可能在夜面亮着城市灯，而 UI 主打真实轨道计算，用户会拿地球当钟表读。
- 月球潮汐锁定用「地心黄经 + 180°」，本初子午线始终正对地球；轨道是椭圆所以**自然产生天平动**（Meeus 级数里已带着几何均速与真实角速的差）。
- 日期/儒略日换算纯 UTC，不受浏览器时区影响；`今天` 按钮与系统日期一致。
- 卫星轨道面跟着母星**平动但不跟着自转**：挂在 `b.grp` 下的 holder 里，`holder.rotation.x = −母星倾角`（与 `axis` 同号），轨道面才垂直母星自转轴。海卫一 `retro:true`。

## 场景比例

**位置关系是真实的**：`SCENE_SCALE = 100`，1 AU = 100 单位等比摆放，所以能看到水星跑得飞快、海王星几乎不动、冥王星轨道明显倾斜且偏心。

**星球直径同样是严格 1:1 真实比例**（默认滑块 `×1`，不放大）。这是本轮修掉的一个真实缺陷——旧实现用幂律压缩，画面尺寸与面板里的真实直径读数对不上：

### 天体显示半径

```js
bodyRadius(km) = km/AU_KM × 100 × sizeMul        // 纯线性，所有天体共用同一个倍率
sizeMul        = sliderToSize(v) = 20000^(v/1000) // 滑块满量程 ×20000，**不取整**
                                                  // 默认 v=0 → ×1（1:1，不放大）
```

关键点：**比值与 `sizeMul` 无关**。因为 `bodyRadius` 是 `km` 的纯线性函数，任何倍率下「木星/地球」都恒等于 `69911/6371 = 10.973`。`verify.js` 里有两条直接钉这个性质的断言：10 个天体的「显示半径 ÷ 真实半径」必须逐位相等（误差 < 1e-12），以及木星/土星/水星/冥王星相对地球的比值必须严格等于真实比值。

默认 `×1` 时地球显示半径是 **0.00426 单位**（真实场景尺寸），在默认机位（≈440 单位外）只有 **0.016 像素**——这是"1:1 不放大"的必然结果，不是渲染故障。要看清楚必须手动拉「星球大小」滑块（×1500 时地球约 12 px）。开「真实星球大小」时 `bodyRadius` 直接返回真实值，与 `×1` 档数值完全相同，**滑块同时 `disabled` 并变暗**。

**拖动为什么以前会"跳帧、不连贯"（用户第 4 条），两处都有份**：

- `sliderToSize` 里那个 `Math.round`。满量程是 ×1 → ×20000 的指数映射，低倍端 `d(sizeMul)/dv` 很小，取整后**连续几十档滑块算出同一个 sizeMul**，画面当然一动不动；到高倍端取整粒度又远小于步长，变成"忽大忽小"。去掉取整，`sizeMul` 全程是浮点数，1000 档逐档单调、无平台（Node 里断言：1000 步全部严格递增，且 `fmtSize` 按量级收窄小数位——`×1.00 / ×12.3 / ×1500`，所以读数不会显示一串没有意义的浮点尾数）。
- 每个 `input` 事件都同步做重活。一次拖动轻松发出上百个事件，而其中每一次都在重建全部行星折线轨道（`refreshPaths`）——主线程被拖去做与"换个大小"无关的几何重建，帧与帧之间就出现空洞，看起来正是"跳帧"。现在 `input` 只写一个 `sizeMulPending`（并立刻刷读数，读数必须跟手），真正的应用由主循环里的 `applyPendingSize()` **每帧结算一次**；同时把"要不要重建"拆成两个脏标记：`pathsDirty`（行星折线，只有距离口径变了才需要）与 `moonDirty`（月球/卫星折线）。拖动大小滑块时行星折线**一条都不重建**——断言用 `__pathsRebuilds` 计数器证明：拖满 1000 档前后计数 138 → 138，而 `moonDirty` 为真（卫星距离确实要重算）。暂停状态下拖动也照样生效（结算点在 `update()` 里，不依赖时间推进）。

### 太阳：也吃滑块，与行星同一口径

严格等比之后太阳不再特殊：它和行星走**同一个** `bodyRadius`，所以「太阳/地球 = 109.198×」在画面和面板里完全一致。

旧实现是两套口径：太阳不吃滑块、`sizeMul` 锁在 `SUN_SIZE_REF = 1500`、半径恒为 17.14 单位，而行星走幂律压缩——于是画面里太阳只有地球的 7.2 倍（真实 109 倍），与信息卡里「直径（光球）1,391,400 km」自相矛盾。

> **代价（用户已确认接受）**：严格等比下太阳半径是水星的 285 倍、地球的 109 倍。默认 `×1` 时太阳 0.465 单位、水星近日点 30.75 单位，完全没问题；但一旦把滑块拉大，太阳会**先于行星**胀出画面并吞掉水星/金星的轨道（×1500 时太阳半径 697 单位 ≫ 水星轨道 30.75）。这是"全部严格等比（含太阳）"的数学必然，不是 bug：真实太阳本来就能装下 1000 个木星。

### 发光体尺寸

辉光不再是绝对常数，改为**跟着太阳半径等比**：

```js
sunGlow.scale = sunR × SUN_GLOW_RATIO        // SUN_GLOW_RATIO = 3.14（直径比，≈1.57× 半径）
```

旧的 `SUN_GLOW_BASE = 54`（半径 27）是"太阳恒 17.14 单位"时代的常数。太阳回到真实比例后（`×1` 时 0.465 单位），54 单位的辉光会比日面大 58 倍，把水星近日点以内的整片区域糊成一块光斑。改成本比例乘子后，任何倍率下辉光都只是"贴着日面的一圈柔光"，不会失控。

| 量 | 表达式 | 默认 ×1 时的值 |
|---|---|---|
| 太阳半径 | `695700/AU_KM × 100 × sizeMul` | 0.465 单位 |
| 辉光 sprite 半边长 | `sunR × SUN_GLOW_RATIO / 2` | 0.730 单位 |
| 黄道轴内端 | `sunR × SUN_GLOW_RATIO × 1.2` | 1.752 单位 |

**硬边日冕环（`corona`）已按用户要求整体删掉**，只留上面那张加色辉光 sprite。它的原形是 `RingGeometry(1.0, 1.35)` 平铺在黄道面里（`rotation.x = -PI/2`）、`opacity:0.16` 的一个多边形，内外两条边界是**解析硬边、没有任何衰减**，于是：

- 侧视（贴近黄道面）时它退化成一条横穿画面的亮带；
- 相机一进外缘以内（跟随水星时很容易）就是"上半屏一块灰色挡板"——评审问题 #42 的**根因**，之前只是把尺寸压小让它不容易发生；
- 它与辉光半径重叠处被加色叠出一个更亮的圈，看着像贴图裂环。真正的日冕形态本来就该是"由内向外连续衰减的辉光"，sprite 那张径向渐变已经是那个形态，这一层除了制造硬边没有别的作用。

> 顺带记一条踩过的坑：`RingGeometry(1.0, 1.35)` 的外缘是 `scale × 1.35` 而不是 `scale`。旧写法上限 `clamp(...,10,26)` 自认"26 很安全"，实际画到 **35.1**，仍越过水星近日点。删除一个 mesh 要一次查四处：**创建、每帧 scale、`window.__solar` 导出、文档里的尺寸约束**——导出列表里留一个已删除的 `const` 会让对象字面量求值当场 `ReferenceError`，整个 `__solar` 挂不上，验证脚本全线 `undefined`。这次改辉光同样踩到：`SUN_GLOW_BASE` 删除后必须把导出改成 `SUN_GLOW_RATIO`，否则一样全线挂掉。现在 `verify.js` 钉住：太阳组里没有 `RingGeometry`、`'corona' in __solar === false`、辉光半径严格等于 `sunR × SUN_GLOW_RATIO / 2`。

辉光保持 `depthTest`：试过 `depthTest:false` 来提亮圆盘，副作用是加色辉光穿透空间，把金星/水星罩进加色区——实测金星夜面亮度从 <40 升到 69.4，夜里凭空看到行星。只用 `renderOrder` 排在实体之后。

### 月球距离

```js
月轨半径 = 地球日心距 × MOON_ORBIT_FRAC (= 0.20)      // real 模式，恒约 20 单位
```

倍数**不再挂在 `bodyRadius(6371)` 上**：那个函数带 `sizeMul` 因子，一调大小滑块月轨就等比跟着缩——星球放大 10 倍时月轨也 ×10，跑到完全看不见的地方；缩小时又挤进地球里。地球**日心距**只由距离模式决定，与大小滑块无关。

| 距离模式 | 倍数 | 月轨半径 | 地球位置 |
|---|---|---|---|
| 真实距离 | ×77.8 | 20.0 单位（默认 ×1 时地球半径只有 0.0043，约 4700 倍） | 100 单位 |
| 对数压缩 | 按**地球所在处的局部对数斜率** `2850/(LOG_SPAN·ln10·au)` | 1 AU 处约 0.76 单位 | 1913 单位 |

对数模式原来走 `mapMoon → mapAU(0.00257)`，那是 `LOG_LO` 端、恒等于 **150 单位**——同期地球 1913、金星 1818，月球轨道半径比"金星↔地球"的间距还大，等于月球在绕太阳跑，而面板写着「×1」。

两个开关的联动：真实地月距只有 0.257 单位。旧版地球显示半径被夸大是 2.39 单位，只开「月球真实距离」而地球仍是夸大的，月球会直接埋进地球模型里，看不到任何东西，所以那时必须联动打开「真实星球大小」。**现在默认就是 `×1` 真实比例**（地球 0.00426 单位 ≪ 0.257 单位），「月球真实距离」单独打开也不会埋球；联动仍然保留——因为用户把「星球大小」滑块拉大之后（比如 ×1500，地球半径 2.39 单位），只开真实月距一样会把月球塞进地球里。

**始终是乘性缩放**，不是 `Math.max(真实, 最小可见值)` 那种截断——截断会把 ±14% 的真实远近起伏压成常数，且让月球嵌进地球内部。唯一保留的 `Math.max` 是**下限保护**：地球显示半径很大时（滑块拉高或真实大小模式下地球缩到 0.004），月轨至少要是「地球显示半径 + 月球显示半径 × 1.5」，避免埋球；`×1` 默认档下这条保护不生效。

```
月球位置 = 地心黄道坐标（moonGeo） + 地球日心场景坐标（已过 mapAU）
```

锚点必须复用行星循环算好的 `planetBodies[2].pos`。曾直接拿 `planetState` 的原始 AU 当锚点：地球实际在 100 单位处，锚点只有 1 单位，于是月球整体落在太阳边上。这类错误静态断言抓不到，只有执行真实几何路径才暴露。

### 环系

土星环按真实间隙半径画：D→F 环、卡西尼缝 1.95–2.02（2:1 共振清空，几乎真空）、恩克缝 2.214。天王星 8 条窄环（ε 环系统，1.64–2.01 R）、海王星 4 条（1.69–2.56 R）。窄环在 1024px 贴图上每条只有约 28px 宽，`opacity` 低于 0.5 几乎看不见（实测 0.34 时截图里只剩几条极淡的灰线，等于白加）→ 天王星提到 0.68、海王星提到 0.58。

**环不跟着星球自转，环自己按开普勒第三定律差动转**（用户第 3 条问的就是这个："环状的是什么、该不该跟着旋转"）。答案是**该转，但不能跟着星球的自转一起转**：环不是刚体，每一圈环带独立绕土星公转，周期 `T = 2π√(r³/GM)`（`GM_土星 = 3.7931e7 km³/s²`、`R_eq = 60268 km`）——D 环 0.20 天、C 环 0.24 天、B 环中心 1.74 R 处 **0.401 天**、A 环 0.57 天、F 环 0.62 天。对照土星本体的自转周期 0.444 天：环内侧比星球转得快、外侧比星球转得慢，共转半径在 1.86 R（正好落在 B 环里）。所以"把环的旋转绑到 `b.spinAng` 上"是**物理错**的，绑上去还会让外侧看起来在倒退。

实现上只有三行，但每一行都有一个坑：

- **几何自建、`u = 归一化半径 / v = θ/2π`**（`RingGeometry` 的 UV 沿周向随 `cosθ` 变化，会把径向缝隙扫成 256 条辐射条纹，见「渲染」一节）。片元里 `rr = mix(uR0, uR1, vUv.x)` 还原半径，`th = vUv.y·2π − uSpinPhase·(uRefR/rr)^1.5`——`(1.74/rr)^1.5` 就是开普勒的角速度比，参考半径与参考周期都从页面常量 `RING_REF_R / RING_REF_PERIOD` 走 uniform 传进 shader，**不写死 1.74**（写死的话改半径时着色器不会报错，只会静默变味）。
- **`b.rings.rotation.z = -b.spinAng·D2R`**：环网格挂在 `-90°` 翻转过来的组里，直接把组的自转算进去会让环面偏离赤道面。用欧拉角 XYZ 顺序展开是恒等式 `Ry(spin)·Rx(−90)·Rz(−spin) ≡ Rx(−90)`（因为 `Rx(−90)·ẑ = ŷ`，绕世界 Y 的自转在环面坐标系里就是绕它自己的法线转），所以补一个反向 `z` 就能**既让环留在赤道面、又抵消掉地壳的自转**，环面的倾角/进动仍然完全跟着星球走。
- **相位不取模，改限帧速**：`RING_STEP_CAP = 12°/帧`（与 `SPIN_STEP_CAP = 14` 同一思路）。原本想对 360 取模，实测立刻出问题——每个环带回到原相位所需的帧数不同（`(1.74/rr)^1.5` 决定的），取模会让某些半径在取模那一帧整体跳相，屏幕上就是"环闪一下"。限速只影响推进速度、不产生跳变。最大流速下不封顶是 5461°/帧，封顶后 60 帧累计 720°（Node 里断言，见验证表 4.9）。

**质感**（同一轮）：环的纹理是轴对称的，纯靠亮度带根本看不出它在转，所以片元末尾叠了一层方位角扰动 `spk = sin(2θ+7r)·0.5 + sin(3θ−1.1)·0.35 + sin(5θ+0.7)·0.15`，`azK = 1 + spk·0.10` 同时调制亮度与不透明度（±10% 的明暗斑驳 = 环面上的密度团块），差动旋转才有可见的载体。径向那边把密度抖动从 2600 条降到 900 条：2048px 贴图上 2600 条随机细缝已经低于采样率，缩到屏幕上会变成灰雾而不是缝。

**故意没做**：环影投在星球上（需要给 `MeshStandardMaterial` 挂 `onBeforeCompile`，改动面与收益不成比例）、环的螺差动旋臂（真实环的螺旋密度波尺度远小于这里的可见分辨率）。

真机（软件渲染）验证：把相位从 0° 推到 30°，环左段取样框内 **70.8% 的像素发生变化**（最大亮度差 9/255），而同一框的**平均亮度 91.49 → 91.41（差 0.08%）**——"图案在动、环不会忽明忽暗"正是差动旋转该有的表现。见「本轮已看过画面」一节。

## 相机

三个状态：`idle` 自由 / `fly` 飞行中 / `follow` 跟随。

**帧率无关的指数平滑**：`f = 1 − exp(−rate·dt)`。不同帧率下观感完全一致；`lerp(target, 0.14)` 是每帧固定步进，144Hz 屏上的跟随速度会比 60Hz 快一倍多（实测拖拽中途松手，两种帧率的惯性残留差 **29.5%**，这就是"不丝滑"的根源）。`lib/OrbitControls.js` 为此打了补丁：r147 的阻尼同样是每帧固定衰减，改法是 `keep = (1−df)^dtScale`，`dtScale = clamp(dt*60, 0.25, 3)`，在 60fps 下与原版**逐位一致**。

点击天体不再瞬移，用 easeInOutCubic 飞过去（0.42–1.1s，按距离自适应）；跟随移动时 target 与距离分别平滑（rate 9 / 6），行星快速公转时不掉队；缩放移除了 6% 死区（那是卡顿感的直接来源）。

**距离下限统一收口**。`controls.minDistance` 原来是与天体无关的常数 0.02，地球半径 2.39 时相机能推到 0.02、直接钻进球心。现在所有"期望距离"路径（`autoDistFor` / `applyZoom` / follow / `reframeAfterSizeChange` / `poseFor`）都走 `clampDist()`，下限 = `max(ZOOM_MIN, 当前天体半径×2)`，并且 `camera.near` 同步跟随——否则近裁剪面会把球切掉。该下限是**随倍率动态**的：默认 `×1` 时地球半径 0.00426 → lo = 0.0085；滑块拉到 ×1500 时地球半径 6.39 → lo = 12.8。

**观察距离滑块的区间随天体现算**。旧映射写死 `0.004 → 200000`（号称跨 7.7 个数量级）却把结果夹到 2R，实测聚焦地球时滑块 0/100/250 三档相机全停在 9.4–9.5 单位（太阳端死区 55%、木星 46%、地球 40%），只有 500 以后才开始动。现在 `zoomRange()` 的下端直接取 `computeMinDist()`，上端保留 20 万单位，整条滑块从头到尾都有效，读数也不再谎报范围。滑块与滚轮是**同一个缩放源**：`sliderToDist` / `distToSlider` 互为反函数（实测 0/137/500/862/1000 五档往返误差 0），相机一动就回填滑块拇指，"读数—滑块—相机"三者永远一致。旧实现只有一半链路：滚轮会写滑块，但相机自己动了不回填滑块，`重置` 后两者读数互斥（滑块拇指停在 1000 = 17.6 万单位，读数显示 0.4 千单位，下一次滚轮以 `zoomUser=176476` 为基准 → 相机猛地弹回远处）。

**滚轮**：自定义 handler 独占缩放，`controls.enableZoom = false`。两条路径都响应同一事件会叠加（实测一格滚轮实际 1.05× 而滑块显示 1.24×）。滚轮不走缓动（`applyZoom(1)`），滑块走 0.28 阻尼——每格只改 1.18 倍距离，若滚轮也走 0.28 缓动，一格只走 5%，滚起来非常迟钝。同时只处理**落在画布上**的滚轮（旧实现挂在渲染元素/window 上无条件 `preventDefault`，指针停在左面板滚动也在缩放——实测相机距离 5.33→4.89，想滚长长的天体列表结果在缩放），`deltaY===0` 不动作（纯横向触控板滑动、惯性尾帧曾被当成"放大"），`ctrlKey`（浏览器把双指捏合报成 ctrl+wheel）走同一条缩放路径而不是被吞掉。

**跟随**是看得见、也能关的显式状态（`bFollow`，带 `aria-pressed`）。开启 = 相机 target 每帧追选中天体；关闭入口有六个：点「跟随」、鼠标拖拽平移、方向键平移、点空白处、`全览`、`Esc`（原先还有一个方向盘中心 `✥`，它随方向盘一起删掉了）。旧实现里只有方向盘的 `panBy()` 会置 `follow=false`，OrbitControls 写的 `controls.target` 没有任何监听接管，而跟随分支每帧又把 target 往选中天体 lerp——实测聚焦地球后右键拖拽三次，与地球位置差 94→137→174 单位，接着又被吸回去；文档却写"平移会脱离跟随"，与实现正好相反，用户读到的是"平移坏了"。方向盘 `✥` 原来只 `controls.target.set(0,0,0)`、不动相机、不清选中，跟随下约 0.1 秒又被吸回，CSS 还给它 `cursor:default` 并排除在 `.pad:active` 反馈之外——看起来像禁用、点下去像坏了。它后来一度改成"解除跟随 + 平滑回到看太阳 + 播报"，再随后随方向盘整体删除——那两件事现在由 `↺ 重置视角(R)`、`Esc` 和"点空白处"分担，`panBy()` 本身留着给全局方向键用。

**自动 / 全览是两个不同的落点**。「全览」按当前尺度现算：覆盖半径 `R = fitRadius()`（可见天体的日心距 + 自身显示半径，轨道线开着时含最外圈 3948 单位），相机距离 = `R / sin(半视场角)`，半角取**垂直与水平里更小的那个**（只看 `camera.foV` 的话，窄窗口/竖屏的水平视场更窄，左右照样被裁）。旧「全览」在真实模式固定停在 (150,205,330)（模长 ≈416），实测点完有木星 sx=−188、海王星 −7492、冥王星 sy=−334 —— 按钮写着全览，画面里 5 颗行星在屏外；而「自动」在同一目标下也收敛到 416.44，两个按钮等效，且 `#bFitAll` 从不进入 `.on` 态、按下去没有任何"生效"反馈。现在全览 10288.9、默认机位 440.6（实测点全览 45 帧飞到 10086、点重置 55 帧回到 446），`#bFitAll` 有高亮态。对数模式下行星轨道全被压在 150–3000 单位的环带里，相机停在 416 意味着一颗行星都不在画面上，看起来像切完模式就黑屏——现在两种模式走同一套现算逻辑，不再有特例。

**大小滑块不重新取景**。取景倍数原是档位硬切 `r<0.6?16:(r<3?11:8.2)`，半径跨过 0.6 / 3.0 时倍数从 16 跳到 11 再跳到 8.2，画面距离猛地一跳。现在：倍数换成连续指数衰减 `frameMulFor(r) = 8.2 + 8.5·exp(−r/0.9)`（相邻 0.02 半径步长的倍数最大跳变 45.5% → 1.12%），并且距离**按半径等比缩放**（`ratio = 新半径/旧半径`），屏幕视角大小完全不变 —— 用户拖滑块的意图是"让星球更大"，不是"让视野跳来跳去"。旧版那个「松手 260ms 后 `flyToPose` 重新取景」的定时器已整体删除（README 里那句"加了 260ms 防抖"就是这么来的，实现里从来没有防抖，只有注释里有个 260）。

**飞行不锁 `controls.enabled`**。旧写法用 `enabled=false` 来"避免手抖抢镜"，而 OrbitControls 的 `onContextMenu` 第一句就是 `if(scope.enabled===false) return;`——聚焦/俯视/侧视/重置之后那 0.42–1.1 秒里右键菜单直接盖在画面上（Windows 菜单）。现在保留 `enabled=true`（菜单照样被 `preventDefault`），只关 `enableRotate/enablePan/enableZoom` 三个具体交互。

另一条更致命的死锁：`flyToPose` 设 `enabled=false`，恢复它的**唯一**入口是 `endFly()`，而 `endFly()` 的**唯一**调用点在 `camMode==='fly'` 的完成分支，`init()` 又把 `camMode` 强改成 `'idle'` → 该分支永不执行 → `endFly()` 永不执行 → 滚轮/拖拽/平移被静默丢弃，**画面纹丝不动，滑块却在动**。修复是在 `init()` 末尾直接调 `endFly()`，而不是手写 `controls.enabled = true`——后者能解锁但内部状态不一致，后续第一次飞行就会再锁死。**凡有「进入置 false、退出置 true」的资源，必须有一条不依赖状态机分支的启动路径兜底。**

**俯视 / 侧视**沿球面最短弧一步转到目标朝向（`Quaternion.setFromUnitVectors`），距离不变、**不脱离当前关注天体**。旧写法两重：`mid=(cur+to)/2` 是"方向中点"，每次点击只走一半路程，连点 3 次才 0.85→0.98（几何级数收敛，永远差最后一点）；而 `setViewDir` 在 `flyToPose` 之后又写 `camMode='idle'; follow=false; endFly();`，飞行在**第一帧就被取消**——症状就是"点了没反应"。

**旋转灵敏度** `rotateSpeed = 0.15`（历史 0.62 → 0.26 → 0.15）。OrbitControls 的换算是 `rotateLeft(2π·Δpx·rotateSpeed/clientHeight)`，即拖过整个画面高度转 `360°×rotateSpeed`：

| 拖动距离 | 0.62 | 0.26 | 0.15 |
|---|---|---|---|
| 225px（1/4 屏） | 56° | 23° | **13.5°** |
| 900px（整屏） | 223° | 94° | **54°** |

0.15 需要拖 2.3 个屏高才转一圈，接近 Celestia / Stellarium 的细调手感；0.62 拖 1/4 屏就转 56°，容易 overshoot 找不回原来的构图。这个参数只作用于鼠标拖拽：俯视/侧视走球面插值，方向键走 `panBy` 平移，OrbitControls 自带的键盘旋转从未启用（`listenToKeyEvents` 只在库里定义、没被调用）。`dampingFactor = 0.075` 管的是松手后的滑行惯性，与灵敏度是两回事，若觉得松手仍晃得厉害要单独调它。

> 测旋转角度不能只调一次 `controls.update()`：开了 `enableDamping` 后 `pointerup` 相机还会继续滑行（`sphericalDelta` 逐帧衰减），量到的是"滑行途中的中间态"，多次测量此消彼长、数据完全不可比。结论以换算公式为准，实测只用来确认"功能仍生效"。

**方向盘按住时切走窗口会停不下来**：原来只有 `pointerup/pointerleave/pointercancel` 三条停止路径，没有 `window.blur` 守卫——按住 ▲ 再 Alt-Tab，那个 40ms 的 `setInterval` 会一直跑，只能回来再点一次同一个键才停。已补。（方向盘后来按用户要求整体删掉，`panBy()` 只留给全局方向键，这条守卫随之退场——但教训留着：**任何"按住持续"的控件都要有失焦停止路径**。）

## 渲染

`antialias` + `logarithmicDepthBuffer` + `outputEncoding = sRGBEncoding` + `ACESFilmicToneMapping`，`toneMappingExposure = 0.62`。光照：`PointLight(0xfff4e0, 3.1, 0, 0)` 在原点（`decay=0` → 无衰减，方向天然正确，无需逐行星计算光照向量）+ `AmbientLight(0x2a3550, 0.10)`。

### 手写 ShaderMaterial 必须自己补全管线

日面、7 个大气壳、土星环、星空这 4 个材质原来都缺 `#include`，写的是**线性深度**，与其余物体的对数深度不可比；同时没走 `<tonemapping_fragment>` / `<encodings_fragment>`，在 ACESFilmic + sRGB 输出下按线性值直出，中间调偏亮约 1.5–2×。补全清单：

```
<common>                        ← 缺它编译失败：logdepthbuf_vertex 的非 EXT 分支要调 isPerspectiveMatrix()
<logdepthbuf_pars_vertex> <logdepthbuf_vertex>
<logdepthbuf_pars_fragment> <logdepthbuf_fragment>
<tonemapping_fragment> <encodings_fragment>
```

`verify.js` 会拿 three 的 `ShaderChunk` 表逐个验证这些 include 名字**真的存在**（拼错的 chunk 名在 three 里是**静默跳过**的，不会报错，也就永远不会生效）。

外观保持不变靠**解一个 `uGain` 标量**（在 Node 里复现 ACES + LinearTosRGB 逐步标定，不是肉眼调）：日面 **1.5**、大气壳 **0.45**、土星环 **0.735**。

### 反照率标定：标量增益，不是改像素

贴图保持原始色度，只解一个 `k` 在 shader 里乘上去（`diffuseColor.rgb *= uAlbedoGain`，注入 `<map_fragment>`）。演进过程：

| 做法 | 问题 |
|---|---|
| 拿贴图灰度当反照率比 | 反照率是**线性**反射率，canvas 存的是 sRGB 编码值，整体错位（测出"月球比水星亮"） |
| Möbius 亮度映射逐通道改像素 | y 接近 1 时三通道一起压向 1，色度被洗掉（海王星深蓝 → 淡蓝，饱和 0.64→0.18） |
| 亮度/色度分离后仍改像素 | 8 位 canvas 会**截断**溢出通道，白改 |
| **只解标量增益** | ✅ 通道比例 100% 保留（但"超出 [0,1] 交给 ACES 滚降"这句当时是**错的**，见下一节） |

标定必须引入 sRGB↔线性转换才能对齐：

```js
function s2l(v){ v/=255; return v<=0.04045 ? v/12.92 : Math.pow((v+0.055)/1.055, 2.4); }
function lumaLin(r,g,b){ return 0.2126*s2l(r)+0.7152*s2l(g)+0.0722*s2l(b); }
```

`ALBEDO_TEX` 里每处偏离真实值都必须写明原因（地球 0.30 因瑞利散射与云、土星 0.42 因环系抬高、冰巨星为保住色度留余量）。Venus 0.689 / Earth 0.434 / Neptune 0.442 / Mercury 0.142 / Moon 0.12 / Mars 0.170 与 NASA 一致。

### 盘面留白：ACES 肩部会把"带对比"整块砍掉

上表最后那格当时写的是"超出 [0,1] 的部分交给 ACES Filmic 的肩部滚降，真实相机传感器过曝时也这样"。**这句话被实测证伪了**：肩部不只是截亮，它压的是**相对起伏**——木星盘面中心送进色调映射的线性值实测 1.81，而 ACES 在那个位置的相对对比保留率只有 13%。逐档扫描（`palette.js` 的 `toneMapBytes`，矩阵与 RRT/ODT 拟合式逐字取自 `lib/three.min.js` 的 r147）：

| 进 ACES 的线性值 | 0.15 | 0.35 | 0.50 | **0.65** | 1.00 | 1.81 |
|---|---|---|---|---|---|---|
| 相对对比保留率 | 63% | 51% | 43% | **33%** | 19% | 13% |

所以褐色带（线性 0.28）与奶白区（0.70）在屏幕上塌成同一个白，"条纹"直接看不见——用户报的"近距离看时带状云纹被洗得发白"就是这一条，跟贴图配色无关（配色那轮已经修好了）。

修法是标定里的**最后一步**：`calibrateAlbedo` 读一次像素同时求"整图均值"（定 `k = 目标/均值`）和"中央 ±20° 均值"，若 `中心均值 × k × 场景辐照 > DISK_KNEE`（0.65），就把 `k` 整体等比压到拐点。等比缩放一点色度都不动，只是变暗，而**暗一点才看得见带**。代价写明白：被压过的天体屏幕亮度不再严格∝反照率（次序仍不乱），因为"亮到看不见结构"本来就不是物理亮度。

```js
const DISK_KNEE = 0.65;                    // 进 ACES 之前的线性值
const ALBEDO_CEN = 20 / 180;               // 只看中心 ±20°：y=sinφ，这块已占掉盘面一半高度
function surfaceIrradiance(){              // 读页面常量，不抄数：调灯光/曝光标定自动跟着走
  return sunLight.intensity * (renderer.toneMappingExposure / 0.6);
}
```

三个数各自被一条断言钉住（第 8 段）：`DISK_KNEE`/`ALBEDO_CEN`/`GAS_PLATEAU` 必须与 `palette.js` 里的同名常数相等，钳位深度必须**除以中心均值而不是全图均值**（构造"中间亮四周暗"的合成图，两个预测值差 3.6 倍，一眼分辨）。

被实测否掉的四条歧路，记下来免得再走：

- **按反照率比例留白**：会把水星(0.142)、月球(0.12) 一起压成黑饼，违反「亮度次序」那条既有约束。
- **全局降光强 / 降曝光**：与增益是**可交换**的，等于什么都没改，只是把整幅画调暗（地球字节均值 105→35）。
- **把 gamma 烤进标定**：对比度反而更差。
- **"把贴图整体压暗"**：贴图线性值降下来，`k` 会被反照率标定**重新顶回去**——标定的存在就是为了保证平均反照率对，任何"从贴图下手改亮度"的尝试都会被它抵消。


### 曝光是色相的真正开关

ACES Filmic 在**肩部会把饱和色往白里拉**。木星曾被误判为"标定值太高"而降到 0.46，实测真因是贴图画错了——贴图修好 + 曝光从 0.92 压到 **0.62** 后，木星就能用真实值 0.538。降曝光而非降光源强度：后者会把水星(0.142)、月球(0.12) 一起压成黑饼。0.62 是扫描 5 档曝光 × 11 颗天体实测的甜点（木星饱和 0.17→0.22、火星 0.62→0.68，而水星 123 / 月球 120 依然可见）。

### 其他物理约束

- **环境光必须极弱**：太空无大气散射，夜面除地球城市灯光外应近乎全黑。`AmbientLight(0.55)` 相对太阳光 `3.1` 是 18% 补光，在真空里等于凭空打光 → 降到 **0.10**。
- **地球夜灯需要昼夜遮罩**：Three.js 的 `emissive` 无条件叠加、不受 N·L 影响，直接设 `emissiveMap` 会让向阳面也冒出城市灯光。注入 shader：`totalEmissiveRadiance *= smoothstep(0.12, -0.22, ndl);`
- **`onBeforeCompile` 是赋值而非链式合并**。地球需要"反照率增益"+"夜面遮罩"两个注入点，后者直接赋值会整个覆盖前者，必须手动保存并串联（`chainPrev`）。曾因此产生回归：`applyAlbedoGain` 先调了一次带 `nightMask` 的链式版本，紧接着又无条件调一次（`chainPrev` 为 `undefined`）→ 覆盖掉带遮罩的版本，夜面遮罩消失、昼面冒出城市灯光。决定性证据是读 WebGL 编译产物（`gl.getAttachedShaders` + `getShaderSource`）：修复前 `fs_uNightSun:false, fs_vWNrm:false, vs_vWNrm:false` —— 变量根本不存在于编译结果里。只看 JS 源码或肉眼看渲染结果都可能误判，**读编译产物是唯一可靠办法**。
- **`RingGeometry` 的 UV 有陷阱**：Three.js 用 `uv.x = (x/outer+1)/2`，沿周向随 `cosθ` 周期变化，会把径向细缝扫成 256 条辐射条纹。土星环改自建 `BufferGeometry`，显式约定 `u = 归一化半径, v = θ/2π`。
- **环的阴影判定必须 `rel = vW − uCenter`**（世界坐标减土星中心）：不减的话土星在约 950 单位外，`s = dot(vW, uSunDir)` 整条环带都会被判进阴影里。
- **气态行星是纬向剪切，不是随机乱线**：木/土/天的云带是东西向风剪切造成的，交界面上卷成沿纬向拉长的涡旋，所以噪声必须**沿经度缓变、沿纬度急变**（`shearX: 5.5, shearY: 19`，噪声团是横扁的），涡旋也必须画扁。⚠ 这一条的注释原来写反了（"经向低频、纬向高频"，跟代码里 `shearX` 管 x=经度正好相反），读注释会以为两个参数调反了。早期版本用随机细线沿经度乱画 120 条，把纬向云带完全盖住，导出贴图一看就是一团乱线球——**贴图应该导出成 PNG 直接看**，这是最快的定位手段。木星配色按真实带系：12 条带按真实纬度排（NEB +12.5°、EZ −0.5°、SEB −17°、NTZ +21.6°…），实测暗带 RGB(160,114,78) / 亮带 RGB(231,208,171)。
- **带剖面是梯形，不是三角形**（`GAS_PLATEAU = 0.55`：内 55% 平顶 + 外 45% 线性过渡）。真实 zone/belt 的交界是喷流剪切的不连续面——边界锐、带身平；三角形 `(1-dd/bw)` 永远只有斜坡，按真实纬度排的带在 ±20° 窗口里首尾相接，于是整个窗口全是斜坡，读出来是"瓦楞"而不是"带"。同一份配色下 A/B（`palette.js disk`）：三角 11.9% → 梯形 **16.3%**。
- **带边要蜿蜒，但不能靠"把边画糊"**（`warp = 0.004` ≈ 0.63° 纬度）。剖面只跟纬度有关 → 带边是一条横跨整个球面的直线，近看就是糖果条纹。做法是整行在 `t±WARP` 各算一次颜色、逐像素用低频噪声在两者间插值，等效于把该行沿纬度推 ±WARP：**边界依然锐，只是不再直**，所以带对比基本不丢（实测钳位后 10.7% → 10.8%）。⚠ 反面教训：想靠加大涡旋笔触的不透明度做质感（`swirlA` 0.07→0.16）实测**更糟**——在奶油色 zone 上甩出一把灰色铅笔线（`/tmp/jup_disk2.png`），细线不是云；`swirlA` 压回 0.06，质感交给 WARP 和 `turb`。
- **大红斑是逐像素"场"，不是描边**（用户目检原话："看起来像个同心靶心，而不像气旋"）。v1 确实是字面靶心：14 层同心晕环 + 实心椭圆 + 同心内环 + 白高光。v2 换成"46 个沿周等分的软块 + 短弧丝"，实测变成**向日葵齿轮边**（等分角度 × 等半径）加一块糊住细节的实心椭圆。v3 不再描闭合轮廓，改成在外接矩形里逐像素算：① 螺旋扭曲后的噪声决定 `core/inner/deep` 怎么掺（内部是缠丝）；② 边界半径只随**角度**抖动（轮廓不规则但仍闭合——气旋本来就是一个团，闭合不是罪）；③ 沿 ±经度指数衰减、再被噪声打散的尾丝。判据也随之换成更准的一条：**颜色不许是半径的单调函数**，具体测法是"同一等距线上的灰阶起伏 > 3× 沿半径的步进"（第 8 段，把缠丝噪声置 0 就能让它变红）。
  ⚠ 这里不要调 `rnd()`：`seed` 是全局的，木星多消耗一个随机数会把后面四张气态贴图整张换掉（改 `swirls` 数量时同理），所以斑点的相位一律从它自己的坐标推。
- **涡旋笔触不能是"实线"**（用户第 3 条「质感再优化一下」的另一处收获）：同一条剪切涡旋，`strokeStyle` 用纯黑/纯白 + 1–3px 实线时，在浅色低对比的土星上导出成 PNG 就是"球面被铅笔刮花"。改成同一条线画三遍（`lineWidth` 3.2×/1.8×/1.0×、`alpha` 0.18/0.35/0.55 倍 `swirlA`）的软边笔触（canvas 2D 没有真高斯模糊，这种叠加是等效做法），颜色改成**从底色插值**（亮=掺白 55%、暗=掺黑 42%）——写死暖白暖褐的话，海王星的蓝球上会画出黄痕。三层叠加后芯部强度约等于原来那一层，所以"看得出有卷曲"没丢，丢掉的只有硬边。另外贴图是环绕的，一条涡旋可能被 0 点经线切成两段：先把点算完再分段 `moveTo/lineTo`，不能靠"画的时候判断越界"——三层叠加时那种判断容易让某一层漏掉一段，接缝就露出来了。
- **大气壳只在边缘增强**：Fresnel 边缘散射 + `forward` 项模拟太阳在行星背后时的前向散射（迎日亮弧）。`strength` 原本只有 0.30–0.42，在深空背景上几乎看不见，整体上调（地球 1.60）。水星不在 `ATMOS` 表里（现实中确实没有大气）；海王星大气壳色必须与本体同调（深蓝 `0x4a72d8`），用浅蓝会把"海王星比天王星深"这个真实身份特征洗掉。

### 地球按地球仪图案绘制

`CONTINENTS` 是 **24 块**真实大陆/岛屿轮廓（按经纬度多边形）：非洲/欧洲/西伯利亚/中国/印度/阿拉伯/东南亚/印尼/日本/菲律宾/北美/南美/澳大利亚/塔斯马尼亚/新西兰/格陵兰/南极洲/马达加斯加/冰岛/不列颠/古巴/斯里兰卡等。

- **必须用 canvas path fill 光栅化**，不能逐像素判点在多边形内——24 块 × 30 顶点 × 52 万像素 ≈ 4 亿次运算会卡死主线程。
- 投影 `x=(lon+180)/360·W`、`y=(90−lat)/180·H`，正好对应球面 UV 展开。
- 海洋深度分档（深海/大陆架/浅海）+ 陆地按纬度分带（极地冰盖/苔原/针叶林/温带/副热带荒漠/草原/季风/赤道雨林）+ 海岸线浅色描边 + 15° 经纬网 + 差异化极冠。
- 夜面城市灯光是 **47 个真实经纬度城市**，严格裁剪在 `LANDMASK` 内。`earthSurface` 与 `earthNight` 共用 `earthLandField()` + `EARTH_LAND` —— 陆地掩膜必须有**单一真相源**，否则阈值一漂移两处就不一致。
- 云层 opacity 从 0.88 压到 **0.55**：它贴在球外 1.012 倍，0.88 时截图里大陆被完全糊成白斑，等于"按地球仪绘制"白做；但也不能降到让地球像裸球，0.55 是"有云感 + 看得见大陆"的平衡点。各向异性 fbm（纬向频率 4× 于经向）模拟纬向风拉成的长条涡旋。云层自转角是地表之上的**附加量 ×0.07**（真实赤道急流比地表快约 7%）；旧写法 `jd*360/0.99727*1.07` 是叠加在 `axis.rotation.y` 之外的独立角，合成后 2.07 倍，云明显超前陆地，读起来像"云在漂移"。
- 纬线在等距柱状投影下本来就是**水平直线**：`g.moveTo(W/2−half, Y); g.lineTo(W/2+half, Y);`，`half = W/2·|cos(lat)|`；经线按 `cos(lat)` 横向收缩，极点自然收敛。**不要用 `ellipse()` 画纬线**——它需要 7 个参数，只传 6 个会抛 `TypeError`，而连带中断顶层脚本的后果是"画面全黑、天体列表为空、所有控件失效"。
- **回读像素的 canvas 必须第一次 `getContext('2d')` 就带 `willReadFrequently:true`**，否则每次 `getImageData` 都在做 GPU 回读，控制台满屏警告。规则里"第一次"是关键：这个属性只在 canvas 首次创建 2D 上下文时生效，后面再传一律被忽略——所以第三、第四次调用补上属性是**没用**的。全页面约 20 处调用点已统一在首次调用处带上；`verify.js` 第 3 段测的就是顺序本身（沙箱把每次 `getContext` 的入参按 canvas 登记下来，取每个 canvas 的**首次** 2D 调用检查属性），并且带一条防假绿：登记数 <10 时报红，否则"一个都没测到"会当成全绿通过。

### 悬浮与标签

**拾取走屏幕空间距离**。行星在屏幕上通常只有 2–5 像素，射线拾取几乎点不中：

```js
命中半径 = max(天体屏幕半径 × 1.6, 13px)     // HALO_MIN = 13
```

13px 的下限保证远处的小行星也能指到，天体靠近时判定区跟着变大。卫星同样参与（`showMoons` 关闭时一并跳过）。左侧「天体」列表也支持悬浮预览，方便在列表里辨认颜色对应的天体。

**3D 光圈已彻底删除**，连同那个每帧空转的 `updateHalos()` 空壳（连调用点一起清了）。原来的光圈是从半径 0.30W 到 0.5W 的**宽亮带**、sprite 按 4.2R 缩放，亮环落在 2.3R–3.4R 处——把整个星球罩在一圈彩色光晕里，配上 `AdditiveBlending` + `depthTest:false`（无视遮挡画在星球之上），视觉上就是"每个星球都套了层大气壳"，连水星/冥王星/月球这些现实中**没有大气**的天体也一律如此，还与真正的大气壳 mesh（`ATMOS`，仅 7 颗有）无法区分。试过"贴边化"改造（亮环移到 1.06R–1.30R、sprite 缩到 2.6R、`depthTest:true`），仍容易被读成大气层，最后整体移除，悬浮反馈交回 UI：标签 `.hl` 放大高亮 + 手型光标 + 悬浮详情卡。

**手型光标**曾经永远不出现：`flyToPose` 里写了内联 `container.style.cursor='default'`，而内联样式压过 CSS 的 `#app.hovering{cursor:pointer}`，加上 `init()` 里的 `select(EARTH,true)` 在首帧之前就执行过一次——从此 CSS 那条规则形同虚设。删掉那行内联样式即可。

**标签避让是二维的**。旧算法只做 1 维 y 位移（每次 15px、最多 8 次 = 120px），水平方向只判 `|dx|<46` 却不挪位、也不钳出视口——滑块拉满 + 常显标签时 11 个标签里 **15 对矩形相交**，中间糊成一竖条（11 个天体在 20 万单位距离下整体只占约 38px）。现在按到相机的距离排序后走 9 个候选位（先上移，再左右让），最后统一钳进视口；全览距离下实测 0 重叠。

**悬浮卡挂在 `#app` 下**。它原来 append 在 `#labels` 里，而 `#labels` 是 `overflow:hidden` + `z-index:5` 的固定层，卡片自身 `z-index:6` 只在这个层叠上下文内有效——面板和底栏（`z-index:10`）直接压在它上面，`translate(-50%,-100%)` 又没有钳制，屏幕顶部约 130px、左侧约 280px 内的天体卡片会被裁掉或整个被压住（从列表项悬浮触发的卡片经常正好落在左面板底下）。现在做边缘钳制。

### 场景分层的三招（网格与轨道线共面 z-fight）

网格圆半径取真实半长轴 `[0.39, 0.72, 1, 1.52, 5.2, 9.54, 19.19, 30.07, 39.48]` AU，行星也用真实半长轴，两者在场景里最近差到 **0.0003 单位**（地球）、0.01（海王星），全览下 0.3 单位 ≈ 0.7px。两者都是透明层、共享 (0,0,0) 组心，three 距离排序打平后按插入顺序画 → 虚线灰圈压在彩色轨道上，而且开关「黄道参考网格」会让轨道线忽好忽坏。另外两条黄道轴线在 `y=0` 上从 ±4200 单位**直接穿过太阳中心**，日面上看得见一根直线。

1. 网格整体下沉 `GRID_Y = −0.9`（**所有顶点同一 y**，只挪 group 的一半会出现斜切面）
2. 网格 `depthWrite:false` 且 `renderOrder=1`、轨道线 `renderOrder=2` —— 不靠距离排序赌先后
3. 黄道轴从太阳外围起画（内端 `IN = max(sunR × SUN_GLOW_RATIO × 1.2, 1e-4)`，随太阳半径自适应；外端 `mapAU(42)`）

## 性能

- **纹理一次生成**：13 张贴图在启动期同步画完（曾测得 `domContentLoadedEventEnd = 5566ms` 全黑）。`TEX.sun` 曾先用 `gasSurface` 生成一张 1024×512、紧接着被 `sunSurface` 整张覆盖——白扔约 190ms + 一张 canvas。现在每张只生成一次，进度由 `#boot` 报。
- **`gasSurface` 的 576 万次对象分配**：色带颜色写在**内层像素循环**里 `new THREE.Color(bcol)`，1024×512 × 11 张 × 4~5 带 ≈ 576 万次，实测多耗约 1.3 秒；基础色只跟纬度有关（与 x 无关）却在每个像素重算。改成色带预解析成 `bandCols`、基础色整行算一次。单张贴图 317ms → 59ms，5 张合计省约 1290ms。
- **轨道折线按需重建**（`pathsDirty` / `moonDirty`）：原来每帧重建 10 条折线共 6489 顶点，其中 38934 次三角函数是**循环不变量**、25956 次 `Math.hypot` 对同三个数算 4 遍，外加 541 次完整 `moonGeo()`（≈10 万次三角函数/帧）与每帧 `computeBoundingSphere`，且都不受 `paused` 保护——实测暂停时 CPU 反而更高（13.25 vs 11.94 ms/帧）。椭圆轨道只随**世纪**级根数进动变化，所以根数没跨 1 天、没换距离模式、没到 500ms 时间片就不重建。暂停时只停时间推进与渲染，UI/相机照常响应，OrbitControls 一动（拖拽、滚轮、阻尼未收敛）就补一帧——既不会看到画面变脏，也不白烧 CPU/GPU。
- **一次 `input` 事件 ≠ 一次重算**（用户第 4 条"拖动跳帧"的性能半边）：大小滑块每帧只结算一次——`input` 只写 `sizeMulPending`，主循环里 `applyPendingSize()` 把它落成 `sizeMul`；同时把脏标记拆成 `pathsDirty`（行星折线）与 `moonDirty`（卫星折线），**改大小不碰行星折线**（`__pathsRebuilds` 拖动前后 138 → 138）。一次拖动上百个事件如果每个都同步重建，主线程就被拖去做与"换个大小"无关的几何重建，帧间出现空洞，用户读到的正是"跳帧"。
- **切换距离模式时先 `disposeGroup` 再 `buildGrid`**：原来 `while(gridGroup.children.length) remove()` 之后不 `dispose()`（全文件 0 次 dispose），连点 10 次「真实距离」`renderer.info.memory.geometries` 从 81 → 181 单调不降（100 次点击 = 1000 个未释放缓冲）。
  ⚠ `disposeGroup` 必须遍历 **`[...g.children]` 快照**：`g.remove(c)` 会 splice 掉 `g.children` 这个活数组，直接 `for...of` 每隔一个跳掉一个（10 个只清掉 5 个），切 12 次模式后网格节点从 10 涨到 19 —— **边修边漏**。这条是 `verify.js` 跑出来的真 bug，静态断言和肉眼看渲染结果都看不出来。
- **DOM 写入前比对缓存**：`updateLabels` 原来每帧写 `innerHTML` + 4 个样式，约 660 次 HTML 解析/秒、1300 个元素节点/秒生灭；`#hDate`、`#vZoom` 每帧重写，`#info` 整个面板 5 次/秒重建。可 `jdStr` 精确到分钟——默认流速下 1 秒才变一次，其余 59 次是白写。现在"值真的变了才写"，实测 60 帧 innerHTML 写入 10 次（每帧一次会是 1800 次）、最慢档 0 次。同理 `getBoundingClientRect` 是"读布局"，紧跟在 DOM 写之后会**强制同步重排**；面板是 `position:fixed`，只有窗口缩放/内容换行才真的变，每 20 帧重取一次、resize 时立刻失效。好消息是原来就没有布局抖动（不在主循环读 `offsetWidth`），DOM 节点数 15 秒稳定在 220。
- **DPR 跟随**：`currentPixelRatio() = min(devicePixelRatio, 2)`，浏览器缩放或拖到不同 DPR 的屏上时，**`setPixelRatio` 只改比例不会自动重建 drawingBuffer**，必须再 `setSize` 一次，否则 framebuffer 沿用旧尺寸、画面持续发糊直到刷新。星空的 `uPR` uniform 也跟着改。resize 本身没做防抖，但不重建贵资源，成本可接受。
- **星空亮度分层**：5200 颗星在 `R=260000` 的球壳上均匀分布、5 档色温，`size = 1.0 + 亮度×2.6 + 2% 抽样 +2.4`。原来用 `PointsMaterial`，它只认统一的 `material.size`，逐顶点辛苦算出的 `size` 属性**根本没进 shader**——于是那 2% 本该 4.6px 的亮星和其他星一样大，星空看起来均匀无层次。改成手写 `ShaderMaterial` + `attribute float size` 后实测尺寸跨度 1.00–5.96px。
- **环系差动也只算便宜的那部分**：环的差动旋转不在 CPU 上逐顶点算，而是片元里一个 `pow(uRefR/rr, 1.5)` + 三个 `sin`（方位角斑驳），每帧 CPU 侧只写一个 uniform（`uSpinPhase`）。相位推进同样限速：`RING_STEP_CAP = 12°/帧`（满档流速下不封顶是 5461°/帧）。**故意不取模**——每个环带回到原相位所需的帧数不同，`%360` 会让某些半径在取模那一帧整体跳相，屏幕上就是"环闪一下"；不取模的代价是 `ringPhaseDeg` 会一直涨，双精度浮点在可预见的会话长度内没有精度问题。
- **自转限速**：`SPIN_STEP_CAP = 14°/帧`（≈840°/秒，肉眼还能读成"在转"）。超过就逐帧追赶而不是瞬跳，同时 HUD 亮起「自转显示已限速」。旧写法是绝对相位 `rotation.y = jd*360/rot`，默认流速下地球每帧推进约 44 圈、木星每帧 145°，实测连续 8 帧纹理相位是 `1.582, 1.582, 0.107, 0.107, 0.107, 0.107, 4.915, 4.915` —— 那是随机闪烁，不是转动。想看清自转必须把流速降到接近最左端，而最左端是 0.0002 天/秒（约 17 分钟/秒），`fmtRate` 还把它印成"0.00 小时/秒"（看着像停了，实际还在走）。现在分档：<1/24 天 → 「分钟/秒」，<1 天 → 「小时/秒」，<50 天 → 「天/秒」，<400 天 → 「月/秒」，更大 → 「年/秒」；滑块单调（最慢 0.0002 / 中点 10 / 满档 365 天/秒）。
- **`dt ≤ 0.05` 钳制 + 后台 rAF 暂停**：切走标签页再回来不会日期大跳。（旧值是 0.1s 上限，配合满档 13.69 年/秒，一次卡顿能让日期跳最多 500 天。）
- **流速默认与滑块位置一致**：曾出现 HTML 写死 `10 天/秒`、滑块却停在 620（`sliderToRate(620)` = 44.4 天/秒），三处文案（`#vSpeed`、`#hRate`、`let rate`）与运行时互不相同——1280×720 冷启动静置 8 秒走完一年，行星在屏幕上绕圈飞，用户以为画面在抽风。现在 160 档正好是 1.00 小时/秒（1 秒 = 1 小时），四处统一；对数换算表补点 `[160, 1/24]`，其余锚点（最慢 0.0002 / 中点 10 / 满档 365 天/秒）不变。

三条硬规矩：

1. **媒体查询必须写在被覆盖规则之后**。同特异度下后写的赢——本轮就抓到一条真实的：`#bInfo{display:none}`（宽屏不该看见详情按钮）写在 `@media(max-width:900px){#bInfo{display:inline-flex}}` **之后**，于是窄屏那条 override 永远赢不了，`ℹ 详情` 按钮在所有宽度下都是死的，而 CSS 一个字都没报错。同类的位置陷阱还有 `max-height:860px` 档写在 940 档之前——两者管的选择器不冲突才没出事，新增覆盖时要按"断点越紧越靠后"排。
2. **断点必须 ≥ 目标视口高度**。`max-height:700px` 覆盖不了 1280×720（720 > 700，规则根本不触发）——注释里写着"720p"而断点写 700，这类矛盾注释比没注释更危险。**这条踩过两次**：另一次是新加的「平移」按钮多占一行，实测左栏溢出 42px、第 11 个天体被裁掉，而 749 > 740 所以 740 档对它不生效。
3. **高度断点不许改宽度**。1280×720 是"又矮又宽"，把面板从 252/296 收到 240/272 之后，信息卡的数值行提前换行，`#info` 从 199px 涨到 216px——省下的 20px 高度被自己吃了回去，列表还得多滚一截。宽度这件事交给 `max-width:900 / 620` 两档（那里 `#right` 是抽屉、`#left` 按 vw 收），高度档只管行距与内边距。

本轮（用户第 2 条"部分还是显示不下，导致有滚动条"）真正的修法不是继续压 padding，而是**把"谁该滚"定下来**：

- `#info`（天体信息卡）改成 `flex:0 0 auto` + `min-height:64px` + 自己的 `overflow-y:auto`，但**排版优先级是"必须看全"**：它按内容自然高，不再被 flex 压扁。以前它是 `flex:0 1 auto`，矮窗口里它先被压缩、内部再滚，用户看到的是"数据卡只剩三行"。
- 真正吃剩余高度的是 `#secBodies`（天体列表段，`flex:1 1 auto;min-height:0`），列表才是**指定的滚动容器**。`fitPanel(rightEl, growEl, minList)` 的第二个参数因此从 `#info` 改成 `#secBodies`——以前传 `#info`/64 在新模型下正好是反的：它会把"不许滚的那块"当成伸缩段去量。
- `.tight` 兜底（整栏可滚）随之必须点名**两块**：`#right.tight > .sec.grow` 与 `#right.tight > #info` 都回自然高、`overflow:visible`。有一条断言专门钉"`CSS 的 .grow` 与 `fitPanel` 的第二个参数指向同一个元素"，否则兜底取消的是没人伸缩的那块。
- 实测收益（`?nogl=1` + 同源 iframe 造真视口，宽度 1440，逐档改高）：`#info` 在 900/860/820/800/768/740/720/700/680/660 全部**零内部滚动**（改前 15–101px），`#left` 到 660 高仍不溢出（改前 660 高溢出 21px、`.tight` 提前触发），30 个列表项**没有一个**名字被截断，右栏底边与底栏顶边恒为 −2px（不重叠）。列表自己在 720/680/660 分别滚 17/13/33px——那是设计内的滚动容器行为，不是"显示不下"。

上一轮排版改造把"用断点硬塞内容"的路线换掉了：**高度不再是瓶颈**。

- 列表区改成容器内部滚动（`#plistWrap`，基准下限 96px、矮窗逐级降到 88/78/70/68px），19 颗行星卫星默认折叠，常驻只有 11 项 + 7 行标题——不再需要"三列才塞得下"那种牺牲分组可读性的断点，`.plist{grid-template-columns}` 现在全文只出现一次（两列，标题与折叠容器都 `grid-column:1/-1` 横跨整行，卫星组在 `.satfold` 里排三列）。断言也从"数 `.plist{` 出现几次"改成真正要钉的那两条：带列数的块只有一个、且它不在任何 `@media` 区间内（花括号配对算区间）。
- 分类标题 `position:sticky` 吸顶，滚到哪儿都知道自己在哪一组；`.cat{display:none}`（旧写法在 740 档里）必须彻底删除，否则连同折叠开关一起消失，那 19 颗卫星就没有入口了。
- **改 class 名要连着改 CSS**（本轮抓到一条真实的静默失效）：卫星容器从 `.grp.sat` 改名成 `.satfold` 之后，那批规则还全写在 `.plist > .grp` 下面，一条都不匹配——最要命的是 `.collapsed{display:none}` 一起落空，"默认收起 19 颗行星卫星"在浏览器里其实没生效（列表照样满 30 项，点标题只是转个箭头）。JS 只切 class、aria 也同步得好，所以 DOM 侧断言全绿；这类断链只能靠**静态 CSS 断言**兜住（`.satfold\.collapsed\{[^}]*display:none` 是否真的在 `<style>` 里）。同时 `.satfold .pl.sel` 必须点名——`.satfold .pl`（`background:transparent`）与 `.pl.sel` 特异度相同而写在后面，不补这条的话折叠区里选中的卫星拿到的是透明底。
- 面板是 `overflow:hidden` 的三段式 flex 列，"挤不下"的那部分不是"要滚才能看到"而是**永久看不见**，所以 `fitPanels()` 量一次：固定段总高 + 滚动区下限 > 面板可用高度时挂 `.tight` 退回整栏可滚（此时标题靠 `.tight > .hd` 吸顶）。判据只累加固定子的 `offsetHeight`，**故意不读 `scrollHeight`**——`scrollHeight` 会随 `.tight` 自己变化，"量→改→再量"的闭环挂在 resize 上就会抖。
- **`.tight` 光给面板加 `overflow-y:auto` 是装饰**：flex 项的收缩量按**容器高度**算，不是按可滚动内容算——`.sec.grow` 照样被 `flex:0 1 auto;min-height:0` 压成一小条，它自己的 `overflow:hidden` 再把带下限的列表区裁掉，固定段仍然顶出屏幕，只是多了一条没用的滚动条。兜底必须逐项**取消内部滚动**：伸缩段回自然高不裁（`flex:0 0 auto;overflow:visible`），`#plistWrap`/`#info` 改成 `overflow:visible`，滚动交给整栏。右栏必须**分开点名两块**：伸缩段是带 `.grow` 的 `#secBodies`，而 `#info` 只有 `.sec` 没有 `.grow`（它的 `flex` 是 id 选择器给的），只写 `> .sec.grow` 覆盖不到它。
- 特异度：`.val` 是单类，会被 `.row span`（类+类型）压掉，所以写成 `.row .val`。右对齐的等宽数字只有读数区需要，被压掉时表现为"数值忽然左对齐、字号变回 12px"，同样不报错。

`#left`/`#right` 的 `max-height` 用 `calc(100vh - var(--bh))`，`--bh` 由 `ResizeObserver` 实测底栏高度写入 CSS 变量：底栏在 ≤1180px 换行后是两倍高，写死 `116px` 必然压住列表（实测 1024×640 左栏底边 443 > 底栏顶边 357，重叠 86px，海王星/冥王星/月球三行看不见也点不到）。天体列表是**切天体的主入口**，被裁就等于功能不可用。

无障碍：所有开关补 `role=checkbox` / `tabindex=0` / `aria-checked`（点击与空格都同步），列表项补 `role=button` / `tabindex=0` / `aria-current` / `aria-label`（卫星会说明母星，聚焦即悬浮、能读出信息卡）；折叠开关额外是 `role=button` + `aria-expanded` + `aria-controls`，**折叠只改可见性、不减可选项**：收起态下 30 项仍在 DOM 里、都能被选中，从画面点进一颗卫星会自动展开它所在分组并 `scrollIntoView`（无布局环境下要 `typeof` 兜底，否则测试沙箱里直接抛）；`:focus-visible` 画出焦点框（原来 `input[type=range]{outline:none}` 且无任何替代，实测连按 12 次 Tab 焦点始终停在 BODY）；`#status` 是 `aria-live=polite` 的播报条，**同时给眼睛（toast）和读屏软件**——平移脱离跟随、解除跟随、日期越界、开关互斥这些原来只改内部状态、界面上零回执的操作现在都有话；快捷键有就地可查的面板（`?` 或 HUD 上的 `?` 按钮），不必翻 README。

**断言从沙箱取真函数、真常量，不在测试里复制公式。** `vm.runInContext` 能看到上一段脚本顶层的 `const`（同一个 realm 的全局词法环境），所以第 8 段直接拿页面的 `gasSurface`/`calibrateAlbedo`/`DISK_KNEE` 来跑。复制公式的测试只会验证"我抄对了"。

**每条新断言都做过破坏性验证**（改坏必须变红，改回来必须全绿）：拐点 0.65→0.75 只红"DISK_KNEE 两边一致"；删掉钳位红两条；把钳位改成除以全图均值，只有"除以中心 ±20°"那条红；剖面退回三角形红两条；缠丝噪声置 0 只红"不是靶心"；带表删掉 SEB 红两条。⚠ 注意第一条的"只红一条"是对的：钳位行为断言用的是**页面自己的** `DISK_KNEE`，改值它跟着走，钉住数值的是那条同步断言——行为与取值分开测，才不会一改常数就满屏红。

**断言的"方向"比数量重要**（用户第 1 条"最小化按钮点了无效"教的一课）。三个 `─` 按钮当时在标记里、CSS 里有 hover、`aria` 也齐，唯独**没有任何一段 JS 引用它们的 id**——而 150 项断言全绿，因为那 150 项全是"正向"的：给定一个实现，检查它对不对；实现根本不存在时，就没有断言去问它。现在第 2 段补了一条反向断言：从标记里抓出所有 `role=button` / `role=checkbox` 的 id，逐个要求源码里以**带引号的字符串**出现（`getElementById('mLeft')` 之类），并先剥掉注释——否则注释里提一句按钮名就能骗过它。这条一上线就把三个死按钮抓了出来，以后再加控件忘接线会直接报红。

**断言的是 UI 可观察行为，不是内部实现。** 沙箱里脚本顶层的 `let` 是**词法声明、不是 sandbox 属性**，`sandbox.jd = x` 那种写法根本写不进去，测试会静默地什么也没测。所以能由 DOM 驱动的开关一律通过**真实事件**驱动（`#dDate` 的 change、`#sSpeed` 的 input、`#mReal`/`#mLog`/各复选框的 click），只有纯函数才从 `__solar` 直接调用——避免把"接线正确"和"逻辑正确"混为一谈。正是这条原则让 `disposeGroup` 那个"隔一个跳一个"的真 bug 被跑了出来的（切 12 次模式后网格节点 10 → 19）。

其它约定与踩过的坑：

- **测试从页面读常量，不自己抄一份目标值。** 目录里曾留着 `_camtest.js` / `_moonchk.js` / `_v2test.js` / `_regress.js`，断言的 `MOON_ORBIT_FACTOR`、`MOON_ORBIT_CAP`、halo sprite 等符号**早已不存在**——代码改了忘了同步会报假失败，而符号删了测试还留在仓库里，比没有测试更糟。现在只有 `verify.js` 一个入口。
- **主循环里加虚拟时钟**（每帧 `vnow += 16.7`）：rAF 的 `dt` 与飞行动画的缓动都依赖时间，用真实 `performance.now()` 会让 45 帧的飞行在测试里只走几毫秒，"相机没到位"被误判成 bug。
- **不能用 `renderer.info.memory.geometries` 判泄漏**（假渲染器没有它），改成统计场景里唯一的 `geometry.uuid`，并给 `BufferGeometry.prototype.dispose` 打补丁记录已释放的 uuid。
- **正则切片要覆盖被引用常量的定义位置**：`MOON_R` / `SUN_SIZE_REF` 若切在片段外会 `ReferenceError`；手动复刻的 `bodyRadius` 必须跟源码同步（含太阳的 `SUN_SIZE_REF` 分支），否则测出来的是一条不存在的通路。
- **注释里留着旧代码会被误判**：`r<0.6?16` 删掉后仍在注释里出现过，断言要先剥掉注释再查。
- **FakeEl 必须实现 `matches` / `closest`**（现代码用它们判焦点控件），元素登记表要从标记里复制 `class`/`attrs`/`tagName`，否则所有"焦点在控件上"的分支都测不到。
- **桩里的"同一份状态两种写法"必须双向同步**，这是排版那一轮里最容易骗人的三处：
  · `className` ↔ `classList`：页面用 `el.className='pl'` 建列表项、用 `querySelector('.cat…')` 读它。`className` 如果只是普通字符串属性，`classList` 就永远是空集——断言拿到"0 个标题 / 0 个列表项"，看起来像页面坏了，其实是桩坏了。
  · `dataset.k` ↔ `data-k`：分组标题用 `h.dataset.k=cls` 写、用 `.cat[data-k="sat"]` 读。不同步的话"每组只建一个标题"的判断恒为 false，沙箱里会建出 30 个标题，测的就不再是页面的行为。
  · 选择器要支持**连写**（`.cat[data-k="sat"]`、`input.ck`）并且 `querySelector` 是**整棵子树**的——卫星被挪进 `.satfold` 容器后，只查直接子节点就查不到它们了。带空格/`>` 的后代选择器宁可显式返回 false，也不要当成一个怪类名去 `contains`（那会产生假阳性）。
- **静态 CSS 断言要先剥注释**：这份文件的 CSS 注释里写着大量"旧写法是这样的"（`.plist{grid-template-columns:1fr 1fr 1fr}`、`.cat{display:none}`），不剥掉就会被正则当成现行规则；同理，`rule(sel)` 这种"取选择器**第一次**出现的块"的写法会读到写在媒体查询里的覆盖（`.padgrid{width:92px}` 在 900 档、位置比基础规则还靠前），判基础规则要改用整段正则。

页面末尾的 `window.__solar` 钩子（源码有明确注释标记）把内部状态暴露给验证脚本：`bodies/camera/controls/renderer/scene`、`mapAU`、`fmtRate`、`sliderToRate`、`sliderToDist`/`distToSlider`、`labelText`、`CONTINENTS`/`buildLandMask`/`LANDMASK`、`clampDist`/`computeMinDist`/`frameMulFor`/`MOON_ORBIT_FRAC`/`moonBoost`、`setViewDir`/`setFollow`/`setAutoDist`、`overviewPose`/`fitAllPose`/`overviewDist`/`defaultPose`/`zoomRange`、`TEX`/`PHYS`/`ATMOS`/`ALBEDO_TEX`、`frame()` 等。

> ⚠ 导出对象里引用一个**已删除的 `const`**，会在初始化时抛 `ReferenceError`——曾把已删的 `MOON_LOOK`/`moonSystems` 留在 `__solar` 里，对象字面量求值就抛，于是**整个钩子挂不上**，测试段全线 `undefined`。

### palette.js · 离线配色与对比度模型

调"这颗星球在屏幕上到底还剩多少带对比"这件事，靠改一版刷一次浏览器是调不出来的（一轮 40 秒，而且看不出是模型错还是配色错）。`palette.js` 是干这个的 Node 脚本，它复现三样东西：`gasSurface` 的逐带 sRGB 插值 + 湍流核（`k ∈ [1−1.35·turb, 1+1.35·turb]`）、梯形剖面、以及**逐字抄自 `lib/three.min.js` 的 ACES 链**（含 `toneMappingExposure/0.6` 那个除数）→ 输出字节口径的均值/峰谷/起伏比例。

- **配置一律从 `index.html` 里解析**（`readGasCfg`：连 `ALBEDO_TEX` 的目标值和光强/曝光一起抓）。手抄一份副本的离线工具，两次迭代之后就是废代码。
- 它同时是 `verify.js` 第 8 段的被测对象之一：两边的常数必须相等，工具才不会讲一套、页面做另一套。
- ⚠ **它的绝对值偏乐观**：同一版它算木星 16.3%，而当时真渲染只有 0.6%（因为贴图正撞在 8 位天花板上）。它的正确用法是**比 A/B、定方向**，"最后看不看得见带"以真截图为准。修好之后模型 16.3% / 实测 10.7%（口径不同：模型看 ±20° 全部行，实测还叠加了球面投影与透视），量级已经对得上。
- ⚠ 模型里没有 WARP，所以它算的带边比真渲染锐。

### 无渲染模式 `?nogl=1`

想在真浏览器里看排版、又不想碰核显（这台 Intel 机器的 WindowServer 曾被 GPU hang 拖死过），直接在 URL 上加 `?nogl=1`：

```
http://127.0.0.1:8777/index.html?nogl=1
```

这条分支**完全不执行 `new THREE.WebGLRenderer`**，改成塞一个 `isNoGLStub` 桩进同样的变量：`setPixelRatio/setSize/render` 是空函数，`capabilities.getMaxAnisotropy()` 返回 1，`info` 给出零值的 render/memory，`outputEncoding/toneMapping/toneMappingExposure` 留成可写的空位。桩对象的 `domElement` 是一块 `id="noglStage"` 的真实 canvas，`setSize` 会把 `width/height` 写成至少 1——因为 `__solar` 的取色函数会 `getImageData(0,0,W,H)`，0 尺寸直接抛 `IndexSizeError`。场景图、纹理生成、UI、主循环、取景全都照常跑，画面按设计留空，状态条会写明"无渲染模式 · 未创建 WebGL 上下文"。`window.__solar.noGL` 暴露当前是否走这条分支。

参数解析故意**不用 `URLSearchParams`**（Node 的 `vm` 沙箱里没有这个全局，用了 `verify.js` 会在脚本顶层就抛），改成正则匹配 `location.search`。`verify.js` 第 1 段因此有三条守门断言：页面确实有 `?nogl=1` 分支、确实没有 `new URLSearchParams(` 调用，以及**把源码里出现过的每一个 `renderer.xxx` 成员拿去和桩比对**——以后谁加了 `renderer.copyFramebufferToTexture()` 之类而没补桩，这条会红，而不是等到浏览器里白屏。

> ⚠ 两个必须知道的坑。① **`file://` 打不开这个模式**：in-app 浏览器会把查询串剥掉（实测 `location.search === ''`），于是照样建了真 WebGL 上下文。要起一个本地静态服务（`node -e` 二十行即可）再用 `http://127.0.0.1:PORT/index.html?nogl=1`。② **别用 `canvas.getContext('webgl2')` 判断"有没有碰 GPU"**：对一个尚未创建上下文的 canvas 调这个函数**本身就会创建**一个 GL 上下文，判断即污染。改用 `stage.id === 'noglStage'` 和 `renderer.isNoGLStub` 这两个正向证据。

### 真浏览器里的画面检查（软件渲染 WebGL）

`take_screenshot` 在这台机器上用不了（in-app 浏览器面板不可见时直接拒：`viewport=0x0, visible=false`），但这**不等于看不了画面**。可行的路子是绕开截图、直接读渲染产物：

1. 在页面里注入一个**同源 `<iframe>`**（`width/height` 就是目标视口，例如 1440×900）。in-app 浏览器自己的顶层视口是 0×0，媒体查询全按 0px 宽求值，量出来的排版一律不可信——这是上一轮那批"531×593 视口"数据的来源问题。iframe 里的 app 有真实布局视口，排版与渲染都正常。
2. iframe 里**不加** `?nogl=1`，让它建真上下文。实测这台 Intel 机器的 Chromium 给的是 `WebGL 2.0 (OpenGL ES 3.0 Chromium)`，即 ANGLE 后端（软件或核显都能出图）。
3. 页面处于 `visibility:hidden` 时 rAF 停摆，所以**手动驱动一帧**：`S.frame('土星', 4)` → `S.update(0)` → `S.renderer.render(S.scene, S.camera)`，然后**在同一个同步任务里**把 `renderer.domElement` 画进 2D canvas。`preserveDrawingBuffer` 没开，跨帧再取就是空图——这是必须知道的第二个坑。
4. 用 `toDataURL('image/png')` 出来，配合 `evaluate_script` 的 `filePath` 落盘、`base64 -d` 还原成 PNG 再看。

这一轮看到的（都是上面这条链路的产物）：

- **土星环贴图本体**（2048×8 的径向条带，纵向拉开展目检）：D 环淡、C 环暗、B 环最亮且密带清晰、卡西尼缝是一条真正的黑带、A 环里能看到恩克缝、最外是淡薄的 F 环。
- **土星近景渲染**：环在星球前后各自半透明叠合、卡西尼缝在斜视下仍分得开，环面与赤道面重合。
- **差动旋转的可见性**：取样框压在环的左侧（不含星球），把 `uSpinPhase` 从 0° 推到 30°，**70.8% 的像素变化**（最大亮度差 9/255），而框内**平均亮度 91.49 → 91.41（0.08%）**。放大差异图能看到变化集中在环面内的斑驳，径向条带位置不动——正是"图案在转、缝不在游动"。
- **顺手抓到并修掉的一个观感缺陷**：类木行星的"剪切涡旋"笔触原来是 1–3px 的**纯黑/纯白实线**（`alpha = turb*0.9`），把贴图单独导出成 PNG 一眼就能看出那是"球面被铅笔刮花"，不是云；土星底色浅、对比低，最明显。改成同一条线画三遍（粗→细、alpha 递增）的软边笔触，颜色从**底色插值**而不是写死黑白（海王星是蓝底，写死暖色会在蓝球上画黄痕），三层合计的芯部强度约等于原来那一层，丢掉的只有硬边。
- **木星近景（本轮）**：`/tmp/jup_disk.png` → `/tmp/jup_disk3.png`。修之前盘面中心字节均值 229（贴在 ACES 肩部），褐色带与奶白区在屏幕上只差 0.6%；修之后均值 184、±20° 窗口内的带对比 **10.7%**，截图上"一条一条"的带直接读得出来，大红斑从同心靶心变成有缠丝与尾丝的旋涡。贴图裁剪 `/tmp/grs_tex3.png` 单独看也确认了内部结构。
- **量带对比时的一个坑：纬度不能按 `t` 线性取**。球面投影是 `y = sinφ`，±20° 已经占掉盘面一半高度，而按贴图行号取"中间 22%"其实量到的是 ±20° 以外的一大片。第一版测量按线性纬度算，把结果虚高了一倍多。
- **取景的三条实测经验**：① `select()` + follow 这条路在沙箱式外部驱动下不会真的接管 `controls.target`（它一直停在 (0,0,0)），所以近景要**手动放相机**：`cam.position = j.pos − dir·r·2.9`；② `dir` 取**指向太阳那一侧**（`j.pos` 归一化后**减**），站到 `+dir` 那边拍到的是全黑的夜面；③ 大红斑在不在镜头里取决于自转相位，所以先按 12 档 `mesh.rotation.y` 各渲一帧、数"高红像素"取峰值那一档（实测峰值 79105 / 谷值 76646，差 3%，够分辨），再定帧截图。
- **新抓到、尚未修的观感缺陷：贴近看时每颗行星外面都有一圈灰边**。已用"关掉 `b.atmo` 再渲一帧"定位到来源是**大气壳 mesh**（关掉后那条环带的高亮像素从 60141 掉到 48763，剩下的 48763 是投影半径公式在 2.9r 处偏小造成的重叠）。机制在 `atmosphereMesh` 的 Fresnel：掠射处 `pow(1−ndv, uPower)→1`，而正对太阳时掠射面的 `dot(N,L)≈0` 经 `smoothstep(-0.30,0.40,·)` 仍有 0.43 → 整圈均匀发亮，读起来像"脏玻璃杯口"。远看只有几像素所以不明显。这条**不在本轮批准范围内**（用户第 3 条已明确收窄为「土星的大环」），所以只记录不擅自改。

> ⚠ 这条链路是**软件渲染**出的图，能证明"着色器编译通过、几何与深度叠合正确、效果肉眼可见"，**不能**证明真机 GPU 上的帧率与深度排序行为（见下）。

### 仍未验证（并说明为什么不能算验证过）

下面这些**只声明为未验证**，不是"已确认没问题"：

- **排版的审美判断**：一行的四等分按钮是否真的读起来像一组、折叠标题的 `▸/▾` 与计数 `u` 的视觉重量是否合适——这些量不出来。可量的部分已经量过了（见「响应式」末尾那组 900→660 的逐档数据）。**注意坑**：页面处于 `visibility:hidden` 时 rAF 停摆，`transition:.14s` 的 `.pl` 会一直卡在起始值上——量选中态要把过渡临时关掉再读，否则量到的是"高亮没生效"的假阳性。
- **#51 帧率**：评审在 SwiftShader 软件渲染下测得默认视角 11.6 fps、拉到最远 4.6 fps，draw call 32→65、三角 48k→142k。绝对值不代表用户 GPU，但"拉远反而贵 3 倍"这个趋势是真实的（远处不再被视锥剔除 + 透明层 overdraw 叠加对数深度关闭了 early-Z）。需要在你这台 Intel 核显上真机复核。

- **`uGain` 标定**：保证的是"与改前的观感一致"（在 ACES + sRGB 管线下的等价换算），不是"与真实天空一致"。
- **海王星仍然顶在 8 位天花板上**：`node palette.js` 报 `gainCal 5.094 / pinPeak 1.69`——同一个机理、更极端的数字（它的 `base:0x1b3a8e` 蓝通道本来就亮，标定为了够到 0.442 的反照率把整体推得很高）。拐点钳位保住了**中心均值**，但保不住**峰值行**，所以它局部还会pin。修法和木星一样是重画配色（把 `base` 的 B 压下来 + 让带表自己承担亮度），这属于另一颗行星的返工，本轮没动。
- **`dark`（海王星大暗斑）与 `cirrus`（天王星卷云）两个分支还是同心晕层**——就是木星大红斑被改掉的那种画法。它们没在真机上按近景目检过，所以既不能说有问题，也不能说没问题；`oval` 那条"颜色不许是半径的单调函数"断言目前只覆盖 `oval`。
- **近景那一圈大气壳灰边**：已定位（见上一节最后一条），未修，等用户确认要不要动 `atmosphereMesh`。
- **贴图生成的启动耗时**：`turb`/`swirls`/WARP 这轮都调高了一档，木星那张多算一遍噪声。实测整页 `DOMContentLoaded` 3.06 s（含 three.js 解析与 11 张贴图），但**没有做改动前后的 A/B**——软件渲染浏览器 + Node 两端都没单独量出贴图这一段。若启动变慢，先量 `gasSurface` 单次耗时再决定回收哪一档。

## 踩过的坑

1. **需要被外部调用的函数不要写成命名函数表达式。** `buildGrid` 曾写成 `(function buildGrid(){...})()`——**命名函数表达式的名字只在函数自身作用域内可见，外部拿不到**。`setDistMode()` 切换距离模式时会调它 → `ReferenceError`；又因为 `setDistMode` 是"先清空网格 → 再重建 → 后重新取景"，异常一抛就卡在中间，导致**网格永久消失**、`distMode` 与实际渲染半径脱节（实测土星半径从 929.9 跳到 2572.4）。"先破坏再重建"的逻辑必须保证重建不会失败。
2. **"同一个状态被两条路径写入"时，要检查每条路径是否都把状态应用到了输出。** 滑块的链路是 `sZoom → zoomUser → applyZoom() → camera.position`，而 wheel 路径只改了 `zoomUser` / 滑块 UI、**漏掉 `applyZoom()`**；更深一层：`zoomUser` 的唯一消费者是 `camMode==='follow' && selected` 分支，默认 `idle` 下**没有任何代码**把它写进相机，于是滚轮完全无效——画面纹丝不动，滑块却在动。改了内部变量、刷了 UI ≠ 生效。
3. **状态机要有不依赖分支的兜底解锁**（见相机一节 `controls.enabled` 的死锁）。
4. **共享的 `THREE.Vector3` 要避开嵌套调用**（`bodyScreenPos` 用专用 `_sp`），否则会互相污染。
5. **凡是进入场景坐标的天体位置，都必须过 `mapAU()`。** `planetState()` 返回 AU，场景单位是 1 AU = 100。
6. **资源释放要遍历快照**（`disposeGroup` 的 `[...g.children]`）。
7. **`onBeforeCompile` 是赋值不是链式合并。**
8. **`setPixelRatio` 之后必须再 `setSize`。**
9. **`PointsMaterial` 不认逐顶点 `size`。**
10. **拼错的 `#include` 名在 three 里是静默跳过的**——不报错，也就永远不生效；验证要拿 `ShaderChunk` 表逐个比对名字是否存在。
11. **`RingGeometry` 的 UV 会随 `cosθ` 周期变化**；它的外缘是 `scale × 外半径系数`，不是 `scale` 本身。
12. **`g.ellipse()` 少传一个参数会把整个 init 打断**，症状是"画面全黑 + 列表空 + 所有按钮是死的"；启动守卫存在的意义就是让这种失败可见。
13. **HTML 里不能用 CSS 注释语法**（`/* … */` 会被当纯文本渲染，左栏糊出一大段说明）；改成 HTML 注释后，注释文本里**不能出现注释的结束标记**，否则提前闭合、后半段仍然泄漏。两次都靠截图发现，静态断言抓不到；现在有一条查左栏 `innerText` 的回归断言。
14. **地球陆地掩膜要有单一真相源**，否则两处阈值一漂移就互相矛盾。
15. **默认倍率不进公式**：`bodyRadius` 一旦混进"默认值"（旧版把太阳锁在 `SUN_SIZE_REF=1500`、行星走幂律 0.42），画面尺寸就与面板里的真实直径读数脱钩，用户拿任何一组数据核对都能发现不一致（实测木星偏差 −75%、冥王星 +165%）。比例正确性的唯一写法是**所有天体共用同一个线性倍率**，默认值只决定"看得见多大"，不决定"谁比谁大"。
16. **"1:1 真实比例"必然导致行星不可见**：默认 `×1` 时地球在默认机位只有 0.016 px（木星 0.17 px、太阳 1.7 px）。这不是渲染故障，是真实尺度的固有结果——太阳系里行星相对轨道极其微小。所以默认档只能二选一：要么缩放（牺牲比例正确性），要么保持 1:1 并接受"必须手动拉大才能看见星球"。本项目按用户要求选后者，并在脚注里写明。
17. **判据本身会失效**：`diskStats().rr` 把半径 `clamp` 到 `g.height/2`，太阳偏大时被截成"半屏高"的假读数（104px 读成 450px）；`meanR` 是整盘平均，而太阳有临边昏暗（边缘压到 30%），天体越大边缘区占比越高、`meanR` 反而越低（42px 时 >120，83px 时 71）——那是**判据失效不是天体变暗**。遍历 scene 找"最大的 sprite"会错抓 halo（未悬停时 `opacity=0、scale=1`）。要判什么就直接读那个被导出的具体量。
18. **屏幕取样类断言的三条铁律**（验证"昼夜遮罩""城市灯光"这类只靠颜色/亮度判断的效果）：① 必须按真实投影取样，不能扫全画布——把背景暖色恒星算成城市灯光后，实测 159698 里真正落在圆盘内的只有约 1000，它还能通过只是因为昼面视角下露出的暖色恒星恰好更少，典型的**假通过**；② 不能拿"昼面暖色 < 夜面暖色"当遮罩判据——昼面沙漠本身就偏暖，实测昼面暖色是夜面的 19 倍，这是**物理正确**的，判据应当用**整体亮度**（实测昼/夜 lit 比 211–404×，遮罩失效则 ≈1）；③ 不能要求"夜面亮点全是暖色"——夜面取景必然带进晨昏线的晨曦弧（冷蓝/白），同一段代码在不同自转角下暖色占比在 37%–100% 浮动，只能判"暖色亮点存在且数量可观"。
19. **测试里正则的转义要嵌进页面 `eval` 执行时**，经过 JS 字符串 → 页面两层转义，极易写错（`/\/\*/` 被转义成匹配不到的模式而误报）。这种场景直接用 `indexOf` 或 `String.fromCharCode(47,42)`。
20. **CDP 消息分发必须回传 id**：`if(o.id && waits.has(o.id)){ waits.get(o.id)(o); waits.delete(o.id); }` —— 缺这一行时 `send()` 的 Promise 永不 resolve，调试脚本表现为"无输出 + SIGTERM"。
21. **文档与实现互相矛盾时，用户读到的是"功能坏了"。** 本轮 P3 表里 13 条"文档说法 vs 实际"，其中至少 5 条的症状是"按钮看起来是坏的"。所以每处修复的代码注释里都写了原来的症状，而这份 README 只描述**当前实现**——它自己就是最后一处需要跟代码对齐的产物。
22. **断言"内部变量等于某值"的测试会在重构时假失败；断言"用户能看到什么"的测试才会在退化时真失败。**
23. **断言还有"方向"问题：全是正向断言的测试集，对"实现根本不存在"是盲的。** 三个 `─` 最小化按钮在标记里、有 hover、有 `aria`，唯独没有任何 JS 引用它们的 id——点了当然没反应，而当时 150 项断言全绿。补的反向断言是"从标记里抓出所有 `role=button/checkbox` 的 id，逐个要求源码里以带引号的字符串出现"，并且**先剥注释**（不剥的话注释里提一句按钮名就能骗过它）。这条自己也要防"抓取器失效型假绿"：markup 一改（换标签、换 role 写法）抓取器可能一个控件都找不到，而 `dead.length===0` 照样通过——所以断言里先要求 `mLeft/mRight/mBottom/bHelp/cOrbit` 这五个已知控件必须被抓到，抓不到就报"抓取器漏了这些控件（断言会假绿）"。
24. **GLSL 写在 JS 模板字符串里，注释里就不能出现反引号。** 一个行内代码标记 `` `uSpinPhase` `` 会把模板字符串就地截断，后半段着色器被当成 JS 解析，报的是 `Unexpected identifier`——症状是整页脚本挂掉（面板齐全、画面全黑），而错误信息完全指不出是"注释"。着色器注释里要指代代码就写普通名字。第 1 段那条"三段脚本全部通过语法解析"的断言存在的意义就是这个。
25. **代理指标会反咬**：断言"列数只在基础规则里定义一次"以前写成"数 `.plist{` 出现几次"。矮屏档加一条完全不碰列数的 `.plist{gap:2px}`，它立刻判红；反过来，真把列数写进媒体查询它反而查不出来。要钉不变量就直接钉不变量本身（带 `grid-template-columns` 的块只有一个 + 花括号配对算出它不在任何 `@media` 区间内）。同类问题还有"用 `renderer.info.memory` 判泄漏"。
26. **`.tight` 这类"兜底"要在真布局里量，不能在沙箱里推断。** Node 沙箱的 `clientHeight` 是 undefined，`fitPanel` 算出 `avail = 1e9`，永远不挂 `.tight`——于是"兜底有没有被摘掉"这类判据在沙箱里必然假绿，只能挪到真浏览器量。同一条规则也解释了为什么"高度断点改宽度"没被任何静态断言抓到：它是布局后果，不是代码形状。
27. **同源 `<iframe>` 是给 0×0 视口的 in-app 浏览器造真视口的唯一办法**，但它有两个代价：① 每个实例都要重新生成 13 张程序化贴图，并发开三个直接把工具调用拖到超时（一次一个 iframe、复用同一个实例）；② iframe 内 `visibility:hidden` 时 rAF 停摆，动画类判据全部失真（见第 18 条与「真浏览器里的画面检查」）。
28. **看效果不一定要截图。** `take_screenshot` 不可用时，`render()` + 同一同步任务里的 `toDataURL()` 一样能拿到真像素（`preserveDrawingBuffer:false` 时跨任务取就是空图）。这一条把"土星环到底长什么样、转起来看不看得出来"从"未验证"变成了可量化的 70.8% 像素变化 / 0.08% 平均亮度漂移。
29. **"描一个闭合轮廓"这条路子本身是错的，换笔触救不回来。** 大红斑 v1 是 14 圈同心晕 + 实心椭圆，看着像靶心；v2 换成"等分角度撒 46 个blob + 实心椭圆 + 弧线"，截图 `/tmp/grs_tex.png` 出来是**向日葵的齿轮边**——等分角度 × 等半径必然周期化，而实心椭圆把内部细节全盖掉了。真正修好的 v3 不再描边：逐像素算一个场（螺旋扭曲 + 只随角度抖的边界 + 指数纬向尾丝），颜色由噪声决定而不是由半径决定。**判据也跟着换成更准的一条：颜色不许是半径的单调函数。** 靶心的本质就是"一圈一色"，只要同一条等距线上颜色随角度剧烈变化，就不可能是靶心——这条已经进了 `verify.js` 第 8 段。教训：同一个视觉缺陷连着两版都用"换个画法描一遍"来修，就说明该修的是画法背后的模型。
30. **"想要质感就加深笔触"是一个被证伪的假设。** 木星带状云纹发白时，我判断"涡旋笔触太淡"，把 `swirlA` 从 0.06 调到 0.16。结果不是"更有质感的云"，而是在奶油色 zone 上甩出一把**灰色铅笔线**（`/tmp/jup_disk2.png`）——笔触是不透明度的加法，加深它只是把同一条硬边画得更实。回退到 0.06，把质感交给 WARP（带边缘按低频噪声蜿蜒）和 `turb`，实测带对比 0.6% → 10.7%，且没有硬线。写进了 `gasSurface` 的注释里，免得下一次又"顺手调深一点"。
31. **全局 `seed` 让一张贴图的随机数消耗波及另外四张。** `rnd()` 与 `noise2()` 共用一个全局种子，按调用顺序推进。在木星贴图里多加一次 `rnd()`，土星/天王星/海王星的整张贴图就会换掉——改动看起来只碰了木星，回归却出现在别处。所以 v3 的涡旋相位改成**从斑点自己的坐标推导**（`ph=(s.x*37.7+s.y*91.3)%6.2832*3.0`），一支随机数都不消耗；`/tmp/sat_disk.png` 用来确认这一点。凡是"给某一处加随机扰动"的需求，先问能不能用位置哈希代替。
32. **量纬度不能按贴图行号线性取。** 球面投影是 `y = sinφ`，±20° 已经占掉盘面一半高度；第一版带对比测量按线性纬度取"中间 22%"，其实量到了 ±20° 以外的一大片，结果虚高一倍多。同一条陷阱还解释了为什么留白判据只看中央 ±20°：近看时"眼睛看见的"就是这一条。页面上的判据宽度已经提成常量 `ALBEDO_CEN`，`palette.js` 里必须同值，`verify.js` 第 8 段直接钉这两个常量相等。
33. **写数值断言时，"条件能不能被触发"和"桩的函数签名是什么"要单独验一遍。** 第 8 段上线时踩了四个：① 拐点钳位只在 `target × surfaceIrradiance() > DISK_KNEE` 时才生效，随手取个 `target:0.12` 会让断言永远走不到钳位分支（静默假绿），得用页面真实的 `ALBEDO_TEX.木星 = 0.538`；② 造贴图那个 `mk(fn)` 的签名是 `fn(x/W, y/H)`，写成 `t => …` 会画出一条**竖条纹**而不是纬向带，测到的是一条不存在的通路；③ 用中点积分算出的均值和页面按行求的均值差 0.8%，`1e-9` 容差直接判红——两边必须用同一个离散口径（从像素数组实测）；④ "±20° 内至少 4 条带"这条天文上就是错的（真实木星是 3 条），改成"≥3 且两半球都有带 + ±5° 内恰好 1 条 = 赤道区"。每一条都配了 `sabotage.py` 的反向证明：改坏源码必须让对应断言变红，否则断言是假的。
