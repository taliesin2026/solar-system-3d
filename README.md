# 太阳系 3D 模拟器

真实轨道计算 + 月球运动的交互式 3D 模拟。纯前端，双击 `index.html` 即可运行，无需联网、无需服务器。

## 运行

直接双击 `index.html`，或用任意静态服务器：

```bash
python -m http.server 8000    # 然后打开 http://127.0.0.1:8000
```

依赖已本地化到 `lib/`，断网也能用。

## 操作

| 操作 | 效果 |
|---|---|
| **悬浮天体** | **显示标签 + 详情卡（距离/周期/速度/直径）** |
| 左键拖拽 | 旋转视角 |
| 滚轮 / 距离滑块 | 缩放（两者联动） |
| 右键拖拽 / 方向键 / 方向盘按钮 | 平移视角 |
| 点击天体 / 左侧列表 | 聚焦并跟随 |
| 俯视 / 侧视按钮 | 视角沿球面平滑转到黄道面法线 / 侧面 |
| `空格` | 暂停 / 播放 |
| `R` | 重置视角 |

### 视角控制

左侧新增「视角控制」面板：

- **距离滑块** —— 对数映射，跨越 **7.7 个数量级**（0.004 → 200000 单位），从贴着星球表面到太阳系全览。滑块和滚轮双向联动，滚轮后会反算滑块位置保持同步
- **自动 / 全览** —— 自动模式按天体大小算取景距离；全览回到内太阳系全景
- **方向盘** —— 上下左右平移，按住持续移动；中心 `✥` 回到太阳。方向键同样可用
- **俯视 / 侧视** —— 沿球面插值转到黄道面法线 / 侧面，不会穿过目标天体

平移会脱离跟随状态（因为你主动接管了视角）。

### 关于悬浮

行星在屏幕上通常只有 **2–5 像素**大，直接用射线拾取几乎点不中。所以悬浮检测走的是**屏幕空间距离**：

```
命中半径 = max(天体屏幕半径 × 1.6, 13px)
```

13px 的下限保证远处的小行星也能轻松指到；天体靠近时判定区域会跟着变大。悬浮后会有淡入的光晕环、标签放大高亮、鼠标变手型，移开即恢复。

左侧「天体」列表同样支持悬浮预览，方便在列表里辨认颜色对应的天体。

想看全景可勾选「常显全部标签」，一次性显示所有天体的名称和实时日心距离。


## 精度说明（已实测验证）

行星位置使用 **JPL SSD 近似轨道根数表**（适用于 1800–2050），月球使用 **Jean Meeus《Astronomical Algorithms》第 47 章** ELP2000-82 截断级数。

与 JPL Horizons 官方星历（VSOP87/DE441）在 2026-10-07 的比对结果：

| 天体 | 三维位置残差 | 折合角距 |
|---|---|---|
| 金星 | 1,108 km | 0.04′ |
| 水星 | 1,906 km | 0.10′ |
| 地球 | 6,350 km | 0.15′ |
| 火星 | 29,015 km | 0.43′ |
| 木星 | 458,370 km | 1.98′ |
| 海王星 | 701,604 km | 0.54′ |
| 天王星 | 812,091 km | 0.96′ |
| 月球 | 80,622 km | 1.9′ |

其他已验证项：
- 地球日心距离全年逐月与 `r = a(1−e·cos E)` 解析解一致（差 1e-14）
- 地球日心黄经年均行度 0.98559°/天（真值 0.98561°/天）
- 地球日心速度 29.78 km/s（真值 29.78）
- 月球地心距离全年 357,198–404,755 km（月地距离变化范围约 356,400–406,700 km）
- 月球黄纬始终落在黄白交角 ±5.145° 带内
- 开普勒方程牛顿迭代残差 < 1e-13°
- 悬浮详情卡轨道速度与 `√(GM(1+e)/(a(1−e)))` 解析解相对差 0.000%（九大天体全部验证）

> 注意：根数表有效期为 1800–2050 年。跳到该范围之外的日期会有明显漂移。

## 关于比例显示

**位置关系是真实的**，按 1 AU = 100 单位等比摆放，所以你能看到水星跑得飞快、海王星几乎不动、冥王星轨道明显倾斜还偏心。

但**星球体积和月球距离做了放大**，原因很直接——真实比例下地球只有 0.0043 个单位，等于一个像素都不到。

- 星球大小默认放大 ×1500，滑块可调 1–20000 倍，或勾选「真实星球大小」
- 月球距离放大 ×93（**乘性**，不是截断），完整保留真实的 14% 远近起伏
- 「对数压缩」模式把 0.39 AU 到 39 AU 压进可视范围，方便看全貌，但会牺牲真实距离感

### 月球的显示比例是个视觉权衡

月球**确实是绕地球的**：位置 = 地心黄道坐标（`moonGeo`）+ 地球日心场景坐标，轨道线也跟着地球一起平移。

放大倍数不是越多越好，这里有个取舍：

| 轨道/地球半径 | 轨道半径 | 效果 |
|---|---|---|
| 1.9× | 4.5 单位 | ❌ 月球贴在地球表面，看不出在绕地 |
| **10×** | **23 单位** | ✅ 清晰可见绕地，且不喧宾夺主 |
| 60×（真实比例） | 143 单位 | ❌ 超过地球日心距（100），看起来像"月球不属于地球系统" |

取 10 倍，并加一道**上限保护**：地球显示半径会随「星球大小」滑块变化，若只按倍数算，滑块调大时月轨会超过地球日心距，月球又会跑回太阳边上。所以月轨半径额外被夹在「地球日心距 × 30%」以内（`MOON_ORBIT_CAP`），每帧由 `syncMoonBoost()` 重算。

| 大小滑块 | 地球半径 | 月轨半径 | 月/地 |
|---|---|---|---|
| ×1 | 0.03 | 0.3 | 9.8× |
| ×1500（默认） | 2.39 | 23.3 | 9.8× |
| ×5000 | 4.80 | 30.0（触发上限） | 6.2× |
| ×20000 | 10.72 | 30.0（触发上限） | 2.8× |

全程月球都在地球外、都在绕地。真实地月距离的 14% 起伏也完整保留。

> **两个曾经的 bug**
> 1. 早期用 `Math.max(真实距离, 最小可见值)` 做放大，把距离截断成常数——远近变化消失，且月球嵌进地球内部。现在改成乘性缩放。
> 2. `update()` 里算地球位置时漏了距离映射，直接用了 `planetState` 的原始 AU 坐标当锚点。地球实际在 100 单位处，但月球锚点只有 1 单位，于是月球整体落在太阳边上。现在复用行星循环算好的 `planetBodies[2].pos`（已过 `mapAU`），两者永远一致。

### 「月球真实距离」会联动「真实星球大小」

真实地月距离只有 0.257 单位，而夸大的地球显示半径是 2.39 单位——如果只开「月球真实距离」而地球仍是夸大的，月球会直接埋进地球模型里，看不到任何东西。

所以这两个开关做了联动：开「月球真实距离」自动打开「真实星球大小」，关「真实星球大小」连带关掉「月球真实距离」。此时地月比例恢复真实的 60.3 倍 earth半径 : 1。

太阳半径固定为 17 单位（不随滑块无限增大），否则会吞掉水星轨道。

### 关于视角切换

镜头运动全部走**帧率无关的指数平滑**：

```
f = 1 - exp(-rate · dt)
```

这个式子的好处是不同帧率下观感完全一致。老式的 `lerp(target, 0.14)` 是每帧固定步进，144Hz 屏上的跟随速度会比 60Hz 快一倍多——实测拖拽中途松手，两种帧率的惯性残留差 **29.5%**，这就是"不丝滑"的根源。

三个具体处理：

| 场景 | 做法 |
|---|---|
| 点击天体 | 不再瞬移，用 easeInOutCubic 曲线飞过去（0.42–1.1s，按距离自适应） |
| 跟随移动 | target 与距离分别平滑（rate 9 / 6），行星快速公转时不掉队 |
| 缩放 | 移除了 6% 死区（那是卡顿感的直接来源），改为连续过渡 |
| 切换比例 | 天体位置会跳，相机自动重新取景；大小滑块加了 260ms 防抖，拖动中不飞镜头 |
| 飞行途中 | 锁定 OrbitControls，避免手抖抢镜，结束后恢复 |

`lib/OrbitControls.js` 也打了补丁：r147 的阻尼是每帧固定衰减，同样帧率依赖。改法是 `keep = (1-df)^dtScale`，其中 `dtScale = clamp(dt*60, 0.25, 3)`。这个写法在 60fps 下与原版**逐位一致**，向后兼容没有。

### 滚轮缩放

跟随模式下滚轮缩放不再被自动距离强制拉回——你的缩放意图会被记住，退出跟随时才恢复自动取景。

滚轮与距离滑块是**同一个缩放源**：自定义 wheel handler 独占缩放，
`controls.enableZoom = false` 关掉 OrbitControls 内建 dolly。
若两者都响应同一滚轮事件会叠加缩放，导致「实际距离」与「滑块反推的数值」对不上
（实测一格滚轮实际 1.05× 但滑块显示 1.24×）。

滚轮不走缓动（`applyZoom(1)`），滑块走 0.28 阻尼——滚轮每格只改 1.18 倍距离，
若也走 0.28 缓动，一格只走 5%，滚起来会非常迟钝。

## 实现要点

- 黄道面映射为 Three.js 的 XZ 平面，+Y 指向北黄极
- 轨道解算：`L` 平黄经 → `M = L − ϖ` → 牛顿迭代解 `E − e·sinE = M` → 真近点角 → 旋转到黄道系
  - 注意近日点幅角 `ω = ϖ − Ω`，与平近点角 `M = L − ϖ` 是两个不同的量，别混
- 角速率（`aDot`/`LDot` 等）单位统一为**度/儒略世纪**
- **凡是进入场景坐标的天体位置，都必须过 `mapAU()`**。`planetState()` 返回的是 AU，
  场景单位是 `1 AU = 100`。月球锚点曾直接用 AU 原值，导致月球被放到太阳边上——
  这类 bug 静态断言抓不到，靠 `_simtest.js` / `_moonchk.js` 执行真实几何来验证
- 共享的 `THREE.Vector3` 要避开嵌套调用（`bodyScreenPos` 用专用 `_sp`），否则会互相污染
- 光照用一个 `decay = 0` 的点光源，方向天然正确，无需逐行星计算光照向量
- **太阳辉光与星球大小滑块解耦** —— 辉光是 `AdditiveBlending` 的 sprite，若直接乘 `sunR`，滑块拉大时面积会暴涨约 10 万倍，看起来像"光变强"。现改为固定基准尺寸 + 有限幅度跟随（0.61×~3.13×）
- 星球贴图全部由 Canvas 程序化生成（气态行星条纹、大红斑、地球大陆云层、极冠等），无外部素材依赖

## 交互与渲染 bug 修复记录

这一节记录 5 个真实缺陷及其根因。它们的共同特征是**症状与根因相隔很远**，
静态断言或肉眼看都很难定位，靠读 WebGL 编译产物 + 无头实跑才查清。

### 1. `controls.enabled` 永久锁死（滚轮/拖拽全失效）

**症状**：滚轮能联动滑块，但画面纹丝不动；拖拽也转不动视角。

**根因是状态机死锁**，链条有四环：

1. `flyToPose()` 设 `controls.enabled = false`（飞行途中锁定防手抖抢镜）
2. 恢复 `enabled = true` 的**唯一**入口是 `endFly()`
3. `endFly()` 的**唯一**调用点在 `updateCamera()` 中 `camMode==='fly'` 的完成分支
4. `init()` 把 `camMode` 从 `'fly'` 强改成 `'idle'` → 该分支永不执行 → `endFly()` 永不执行

OrbitControls 首行即 `if (scope.enabled === false || ...) return;`，
于是滚轮/拖拽/平移全部被静默丢弃。

**修复**：`init()` 末尾直接调 `endFly()`，而不是手写 `controls.enabled = true`——
后者能让控件解锁，但内部状态不一致，后续第一次飞行就会再锁死。

**教训**：凡是有「进入时置 false、退出时置 true」的资源，必须有一条**不依赖状态机分支**
的启动路径来兜底解锁。

### 2. 滚轮只动滑块不动画面

**根因**：事件链路断在最后一米。滑块的 `input` 路径是
`sZoom → zoomUser → applyZoom() → camera.position`，而 wheel 路径只改
`zoomUser` / `zoomAuto` / 滑块 UI，**漏掉了 `applyZoom()`**。

更深一层：`zoomUser` 的唯一消费者是 `updateCamera()` 的 follow 分支
（`camMode==='follow' && selected`）。默认 `idle` 状态下**没有任何代码**
把 `zoomUser` 写进相机，所以漏掉 `applyZoom()` 就等于滚轮完全无效。

**修复**：wheel handler 末尾加 `applyZoom(1)` + `syncZoomUI()`。

**教训**：「同一个状态变量被两条路径写入」时，必须检查**每条**路径是否都执行了
「把状态应用到输出」的步骤，不能只看它有没有更新 UI。

### 3. `buildGrid` 作用域泄漏 → 切距离模式后网格永久消失

**根因**：`buildGrid` 写成了命名函数表达式 `(function buildGrid(){...})()`。
**命名函数表达式的名字只在函数自身作用域内可见，外部拿不到。**
`setDistMode()` 切换距离模式时会调用 `buildGrid()` → `ReferenceError`。

放大后果的是执行顺序：`setDistMode` 是「先清空网格 → 再重建 → 后重新取景」，
异常一抛就卡在中间，导致**网格永久消失**、`distMode` 与实际渲染半径脱节
（实测土星半径从 929.9 跳到 2572.4）。

**修复**：改用函数声明 `function buildGrid(){}`，并在文件末尾调用一次。

**教训**：需要被外部调用的函数不要写成命名函数表达式；
「先破坏再重建」的逻辑必须整体放进 try 或保证重建不会失败。

### 4. 地球夜面遮罩被覆盖（回归）

这是材质物理化改造时**引入**的回归。`applyAlbedoGain` 直接赋值
`mat.onBeforeCompile = sh => {...}`。地球先调了一次带 `nightMask` 的链式版本，
紧接着又无条件调了一次（`chainPrev` 为 `undefined`）→ **整个覆盖掉链着 nightMask 的版本**，
夜面遮罩随之消失，昼面冒出城市灯光。

**修复**：加 `else` 分支，地球跳过第二次调用。

**决定性证据**：读 WebGL 编译产物（`gl.getAttachedShaders` + `gl.getShaderSource`），
修复前 `fs_uNightSun:false, fs_vWNrm:false, vs_vWNrm:false`——变量根本不存在于编译结果中。
只看 JS 源码或肉眼看渲染结果都可能误判，**读编译产物是唯一可靠办法**。

**教训**：`onBeforeCompile` 是**赋值**而非链式合并（不同于 `material.onBeforeCompile` 的
某些封装库）。多次注入必须手动保存并串联前一个 handler，否则后一次静默吞掉前一次。

### 5. `gasSurface` 的 576 万次对象分配

**根因**：色带颜色在**内层像素循环**里 `new THREE.Color(bcol)`。
1024×512 像素 × 11 张贴图 × 4~5 条带 ≈ 576 万次分配，实测多耗约 1.3 秒。
同时基础色只跟纬度有关（与 x 无关），却在每个像素重算一遍。

**修复**：色带颜色预解析成 `bandCols` 数组；基础色整行算一次。

**实测**：单张贴图 317ms → 59ms，5 张贴图合计省约 1290ms。

### 顺带修掉的两个测试问题

- **CSS 媒体查询位置错误**：响应式规则写在 57~89 行，而基础规则 `.plist` 在 120 行，
  同特异度下后写的赢 → 矮窗口三列布局**完全没生效**。已统一移到 CSS 末尾。
- **测试假通过**：`_rendertest.js` 8b 段扫全画布，把星空的暖色恒星算成城市灯光，
  详见下方「屏幕取样类断言的三条铁律」。

## 材质物理化

材质按各天体的**真实物理特性**重做，标定依据是 NASA/JPL 的几何反照率
（不是 Bond 反照率——几何反照率按定义就是「零相位角时反射回观察者的光比」，
正是肉眼看到的屏幕观感）。

### 反照率标定：标量增益，不是改像素

贴图保持原始色度不变，只解出一个**标量增益** `k`，在 shader 里乘上去：

```glsl
diffuseColor.rgb *= uAlbedoGain;   // 注入 <map_fragment>
```

演进过程中踩过三个坑，最终才收敛到这个方案：

| 做法 | 问题 |
|---|---|
| 拿贴图灰度当反照率比 | 反照率是**线性**反射率，canvas 存的是 sRGB 编码值，整体错位（测出「月球比水星亮」） |
| Möbius 亮度映射逐通道改像素 | y 接近 1 时三通道一起压向 1，**色度被洗掉**（海王星深蓝 → 淡蓝，饱和 0.64→0.18） |
| 亮度/色度分离后仍改像素 | 8 位 canvas 会**截断**溢出通道，白改 |
| **只解标量增益，在 shader 里乘** | ✅ 通道比例 100% 保留，超出 [0,1] 的部分交给 ACES 滚降 |

标定必须引入 sRGB↔线性转换才能对齐：

```js
function s2l(v){ v/=255; return v<=0.04045 ? v/12.92 : Math.pow((v+0.055)/1.055, 2.4); }
function lumaLin(r,g,b){ return 0.2126*s2l(r)+0.7152*s2l(g)+0.0722*s2l(b); }
```

`ALBEDO_TEX` 里每处偏离真实值都必须写明原因（地球 0.30 因瑞利散射与云、
土星 0.42 因环系抬高、冰巨星为保住色度留余量）。

### 曝光是色相的真正开关

ACES Filmic 在**肩部会把饱和色往白里拉**。木星曾被误判为「标定值太高」而降到
0.46，实测发现真因是贴图画错了（见下）——贴图修好 + 曝光从 0.92 压到 **0.62** 后，
木星就能用真实值 0.538 了。

降曝光而非降光源强度：后者会把水星(0.142)、月球(0.12) 一起压成黑饼。
0.62 是扫描 5 档曝光 × 11 颗天体实测出来的甜点（木星饱和 0.17→0.22、火星 0.62→0.68，
而水星 123 / 月球 120 依然可见）。

### 气态行星：纬向剪切，不是随机乱线

木/土/天的云带是**东西向风剪切**造成的，交界面上卷成**沿纬向拉长**的涡旋。
所以噪声必须**经向低频、纬向高频**（`shearX: 2.6, shearY: 15`），涡旋也必须画扁。

> 反例：早期版本用随机细线沿经度乱画 120 条，把纬向云带完全盖住，
> 贴图导出一看就是一团乱线球。**贴图应该导出成 PNG 直接看**，这是最快的定位手段。

木星配色按真实带系：褐色带（NEB/SEB 最宽最深）与奶白色区（zone）相间，
实测暗带 RGB(160,114,78) / 亮带 RGB(231,208,171)，对比 1:1.7。

### 其他物理约束

- **环境光必须极弱**：太空无大气散射，夜面除地球城市灯光外应近乎全黑。
  `AmbientLight(0.55)` 相对太阳光 `3.1` 是 18% 补光，在真空里等于凭空打光 → 降到 **0.10**
- **地球夜灯需要昼夜遮罩**：Three.js `emissive` 无条件叠加、不受 N·L 影响，
  直接设 `emissiveMap` 会让向阳面也冒出城市灯光。需注入 shader：
  `totalEmissiveRadiance *= smoothstep(0.12, -0.22, ndl);`
- **`onBeforeCompile` 要链式组合**：地球需要「反照率增益」+「夜面遮罩」两个注入点，
  后者会覆盖前者，必须用 `chainPrev` 串联
- **`RingGeometry` 的 UV 有陷阱**：Three.js 用 `uv.x = (x/outer+1)/2`，
  沿周向随 `cosθ` 周期变化，会把径向细缝扫成 256 条辐射条纹。
  土星环改自建 `BufferGeometry`，显式约定 `u = 归一化半径, v = θ/2π`
- **地球陆地掩膜要单一真相源**：`earthSurface` 与 `earthNight` 共用
  `earthLandField()` + `EARTH_LAND`，避免阈值漂移
- 地球云层用**各向异性 fbm**（纬向频率 4× 于经向）模拟纬向风拉成的长条涡旋

### 屏幕取样类断言的三条铁律

验证「昼夜遮罩」「城市灯光」这类**只靠颜色/亮度**判断的效果时，
有三个反复踩到的坑，写在这里避免重蹈：

1. **必须按真实投影取样，不能扫全画布。**
   `_rendertest.js` 的 8b 段原来扫 `getImageData(0,0,w,h)`，
   把背景星空里大量暖色恒星算进了「夜面暖色像素」——实测 159698 里
   真正落在地球圆盘内的只有约 1000。它还能通过，只是因为昼面视角下
   星空露出的暖色恒星恰好更少，属于典型的**假通过**。
   现在统一走 `warmDisk()` 钩子，它按 `project()` 得到真实圆盘位置采样。

2. **不能拿「昼面暖色 < 夜面暖色」当遮罩判据。**
   昼面的沙漠/地表本身就偏暖，实测昼面暖色是夜面的 19 倍，这是**物理正确**的。
   判据应当用**整体亮度**：遮罩失效时夜面会和昼面一样亮。
   实测昼/夜 lit 比为 211~404×，遮罩若失效该比值≈1。

3. **也不能要求「夜面亮点全是暖色」。**
   `frame(name, distMul, night=true)` 的夜面取景是「背阳面偏 13°」，
   画面里必然带进晨昏线附近的**晨曦弧**，晨曦是冷蓝/白色的。
   同一段代码在地球不同自转角下暖色占比会在 37%~100% 之间浮动。
   只能判「暖色亮点存在且数量可观」，不能判占比。

另外两条通用约束：

- **CSS 媒体查询必须放在被覆盖规则之后。** 同特异度下后写的赢，
  响应式规则写在文件前部就等于没写。
- **媒体查询的断点必须 ≥ 目标视口高度。** `max-height:700px` 覆盖不了
  1280×720——720 > 700，规则根本不触发。注释里写着「720p」而断点写 700，
  这类矛盾注释比没注释更危险。

### 拖拽旋转灵敏度

`controls.rotateSpeed = 0.26`。OrbitControls 的换算是
`rotateLeft(2π · Δpx · rotateSpeed / clientHeight)`，即拖过整个画面高度才转
`360° × rotateSpeed`。原值 0.62 意味着拖 1/4 屏就转 56°，容易 overshoot
找不回原来的构图；0.26 约为原来的 42%，需要拖约 3/4 屏才转一圈。

| 拖动距离 | 0.62 | 0.26 |
|---|---|---|
| 225px（1/4 屏） | 56° | 23° |
| 450px（1/2 屏） | 112° | 47° |
| 900px（整屏） | 223° | 94° |

这个参数**只作用于鼠标拖拽**：俯视/侧视走 `setViewDir` 的球面插值，
方向键走 `panBy` 平移，OrbitControls 自带的键盘旋转从未启用
（`listenToKeyEvents` 只在库里定义、没被调用）。

`dampingFactor = 0.075` 是控制松手后的滑行惯性，与灵敏度是两回事，
若觉得松手后仍晃得厉害需单独调它。

> 测旋转角度时不能只调一次 `controls.update()`：开了 `enableDamping` 后
> `pointerup` 相机还会继续滑行（`sphericalDelta` 逐帧衰减），量到的是
> 「滑行途中的中间态」，多次测量会此消彼长、数据完全不可比。
> 结论以换算公式为准，实测只用来确认「功能仍生效」。

## 交互与视觉调整（灵敏度 / 平移模式 / 光圈 / 太阳大小）

### 拖拽旋转灵敏度（两轮下调）

`controls.rotateSpeed`：0.62 → 0.26 → **0.15**。

OrbitControls 的换算是 `rotateLeft(2π · Δpx · rotateSpeed / clientHeight)`，
即拖过整个画面高度才转 `360° × rotateSpeed`：

| 拖动距离 | 0.62 | 0.26 | 0.15 |
|---|---|---|---|
| 225px（1/4 屏） | 56° | 23° | **13.5°** |
| 900px（整屏） | 223° | 94° | **54°** |

0.15 需要拖 2.3 个屏高才转一圈，接近 Celestia / Stellarium 的细调手感。

### CAD 式平移模式

新增「✥ 平移」开关（快捷键 `Tab`）。CAD 不是靠右键，而是「模式开关 + 左键当前工具」：

| 状态 | 左键 | 中键 | 右键 |
|---|---|---|---|
| 默认 | 旋转 | 旋转 | 平移 |
| 平移模式 | **平移** | 旋转 | 平移 |

实现上不用改库：OrbitControls r147 的 `onMouseDown` 读 `scope.mouseButtons.{LEFT,MIDDLE,RIGHT}`，
直接换映射即可。中键原本是 `DOLLY`（推拉），但滚轮缩放已被自定义 handler 独占
（`enableZoom = false`），中键空着正好拿来旋转。

按钮下方有一行提示文字，会随模式切换内容。

### 悬停光圈不再是「大气层」

原来 halo 是从半径 `0.30W` 到 `0.5W` 的**宽亮带**，sprite 又按 `4.2R` 缩放，
于是亮环落在 **2.3R~3.4R** 处 —— 把整个星球罩在一圈彩色光晕里。
配上 `AdditiveBlending` + `depthTest:false`（无视遮挡画在星球之上），
视觉上就是「每个星球都套了层大气壳」，连水星/冥王星/月球这些
现实中**没有大气**的天体也一律如此。

改法：

- 渐变亮环贴紧星球边缘（`0.72~0.90` 处，落在 **1.06R~1.30R**），外面全透明
- sprite 缩放 `4.2R` → `2.6R`
- `depthTest: false` → `true`，光圈被星球本体近侧遮住，只露边缘环

现在读起来是「选中框」而不是「大气层」，也不再与真正的
大气壳 mesh（`ATMOS`，仅 7 颗行星有）混淆。

### 太阳不再比地球小

`bodyRadius()` 用幂律压缩 `pow(real, 0.42)` 压缩所有天体，
于是真实 109 倍的太阳被压到只剩 **7.2 倍**（`109^0.42 = 7.2`），
视觉上太阳和地球成了「同级」，看起来太阳甚至更小。

**不能用「给太阳改压缩指数」的办法**——试过，数学上不成立：

- 幂律压缩对所有天体同时生效，太阳 `real=0.465` 与地球 `real=0.00426`
  相差 109 倍，压缩后只剩 7.2 倍，这是幂函数的性质
- 且 `real < 1` 时**指数越大结果反而越小**（`0.465^0.62 < 0.465^0.42`），
  调大指数会让太阳更小——方向是反的
- 指数从 0.42 一路降到 0.18，比值也只从 7.2 拉到 8.6，杯水车薪

最终改为给太阳一个**独立放大系数**（不影响任何其它天体的观感）：

```js
if(km > 1e5) return r * 2.0;      // 太阳
```

结果：太阳/地球 = **14.4×**（原 7×，真实 109×），太阳/木星 = 5.2×，
全览视角下屏幕半径 83px（原 42px）。上限约束是太阳半径必须小于
水星轨道半径 39，否则会吞掉内行星轨道 —— ×2.0 时占 88%，是安全区。

配套要同步的两处（改 `bodyRadius` 时**必须**一起改，否则辉光算错）：

- `k = sunR / 34.28` —— 辉光基准跟随新公式（原来写死 17.14）
- `glowBase = 100`、`corona` clamp 上限 48

**辉光不能给太大**：它是 `AdditiveBlending` 的 sprite，
直径超过实体 ~3 倍就会在画面中央糊成一大团圆盘（加色叠加的结果），
把内行星轨道全盖住。实测 `glowBase=150` + corona 上限 120 时就是一个占屏 1/4 的棕色圆盘。

**辉光不能关掉深度测试**：试过 `depthTest:false` 来提亮圆盘，副作用是辉光会穿透空间
把金星/水星等邻近天体也罩进加色区——实测金星夜面亮度从 <40 升到 69.4，
夜里凭空看到行星。最终保留 `depthTest`，只用 `renderOrder = 3` 排在实体之后。

### 本轮踩的坑

1. **HTML 里不能用 CSS 注释语法**。写 `/* CAD 式操作模式开关…… */` 会被浏览器
   当纯文本渲染，左栏糊出一大段说明文字。而且修的时候又踩了一次 ——
   改成 HTML 注释后，**注释文本里包含了注释的结束标记**，导致提前闭合、
   后半段仍然泄漏。两次都是靠截图发现的，静态断言抓不到。
   已加回归断言：查左栏 `innerText` 里有没有注释内容。
2. **`diskStats().rr` 不能用来判天体大小**：它把半径 `clamp` 到 `g.height/2`，
   太阳一旦偏大就被截断成「半屏高」的假读数（实测 104px 被读成 450px）。
   判大小要用投影公式 `bodyRadius / (dist·tan(fov/2)) · (h/2)`，
   且**必须先 `resetView()`** —— 相机位置不同，同一天体的屏幕半径差几百倍。
3. **`meanR` 不等于「天体亮度」**：它是整个圆盘的平均，而太阳有 `limbDarkening`
   （边缘压到 30%）。天体越大，边缘昏暗区占比越高，`meanR` 越低 ——
   太阳半径 42px 时 `meanR>120`，83px 时掉到 71，那是**判据失效**不是天体变暗。
   已给 `diskStats` 加 `coreR/coreG`（`rad<0.5` 的中心区）并改用它判亮度。
4. **遍历 scene 找「最大的 sprite」会错抓 halo**：halo 未悬停时 `opacity=0、scale=1`。
   要判辉光尺寸就直接用导出的 `S.sunGlow.scale.x`。
5. **测试里正则的转义**：代码要嵌进页面 `eval` 执行，经过 JS 字符串 → 页面两层转义，
   正则里的转义极易出错（`/\/\*/` 被转义成匹配不到的模式而误报）。
   这种场景直接用 `indexOf` 或 `String.fromCharCode(47,42)`。

### 响应式新增 760px 档

覆盖 1384×749。749 > 740，所以 740 档对它是**不生效**的，
而新加的「平移」按钮又占掉一行 —— 实测左栏溢出 14px、「月球」被裁掉。
解决：把 4 个机位按钮排成 **2×2**（而不是 1×4 + 单独一行），
视角控制段从 193px 降到 174px。

**教训（第二次了）**：媒体查询断点必须 ≥ 目标视口高度。
`max-height:760px` 覆盖 749，`max-height:740px` 就不覆盖。

## 第七轮修订（2026-10-07）— 七项需求

### 1. 观察距离下限 = 2 倍天体半径

旧 `controls.minDistance = 0.02` 是与天体无关的常数，地球半径 2.39 时相机能推到 0.02，
直接钻进球心。新增动态下限并**统一收口**：

```js
let _minDist = ZOOM_MIN;
function computeMinDist(){
  let r = 0;
  const b = selected || hovered;              // 优先选中/悬停的
  if(b){ r = bodyRadius(b.def.r); }
  else { /* 否则取离 controls.target 最近的天体 */ }
  _minDist = Math.max(ZOOM_MIN, r*2);
  controls.minDistance = _minDist;
  // ★ near 必须同步跟随，否则近裁剪面会把球切掉
  const near = clamp(_minDist*0.04, 4e-4, 0.02);
  if(Math.abs(camera.near - near) > 1e-9){
    camera.near = near;
    camera.updateProjectionMatrix();
  }
  return _minDist;
}
function clampDist(d){ return clamp(d, computeMinDist(), ZOOM_MAX); }
```

所有「期望距离」路径（`autoDistFor` / `applyZoom` / follow / `reframeAfterSizeChange` /
`poseFor`）统一走 `clampDist`，不会再有任何一条路绕过下限。

### 2. 大小滑块时三处不联动（辉光 / 月轨 / 视野距离）

**① 太阳辉光跟着缩放**
原实现太阳走同一条 `pow(sizeMul,0.58)` 通路，调滑块时太阳/辉光/日冕一起变，
拉满时太阳暴涨吞掉内行星轨道。新增锁定常量：

```js
const SUN_SIZE_REF  = 1500;   // 太阳固定用的滑块基准值
const SUN_GLOW_BASE = 100;    // 与太阳实体 34.28 的比约 2.9×

// bodyRadius 内
const mul = km > 1e5 ? SUN_SIZE_REF : sizeMul;
const r = Math.pow(real, 0.42) * Math.pow(mul, 0.58) * 0.34;
if(km > 1e5) return r * 2.0;               // 太阳半径恒为 34.28
```

实测：滑块 ×1→×20000，太阳半径跨度 **1.000000×**，辉光纯常量。

**② 月球轨道跟着缩放**
原 `MOON_ORBIT_FACTOR = 10` 挂在 `bodyRadius(6371)` 上，带 `sizeMul` 因子。
改为挂在**地球日心距**上（日心距只由距离模式决定，与大小滑块无关）：

```js
const MOON_ORBIT_FRAC = 0.20;              // 月轨半径 = 地球日心距 × 此值
function syncMoonBoost(earthSunDist){
  if(moonReal || distMode==='log'){ _moonBoost = 1; return _moonBoost; }
  const want  = Math.max(earthSunDist, 1e-6) * MOON_ORBIT_FRAC;
  const floor = bodyRadius(6371) + bodyRadius(MOON_R)*1.5;   // 防埋球
  _moonBoost = Math.max(want, floor) / (0.00257*SCENE_SCALE);
  return _moonBoost;
}
```

实测：滑块 ×1→×20000，月轨 19.46~19.50 单位，跨度 **1.002×**（旧版跨度 566×/1.8×）。
默认滑块下月轨 = 8.1 倍地球半径，近地点月球仍在地球外。

**③ 视野距离跟着跳**
两处根因：
- 取景倍数用档位硬切 `r<0.6?16:(r<3?11:8.2)`，半径跨过 0.6 或 3.0 时倍数跳档。
  改为连续指数衰减：`function frameMulFor(r){ return 8.2 + 8.5*Math.exp(-r/0.9); }`
  实测相邻 0.02 半径步长的倍数最大跳变 **45.5% → 1.12%**。
- 「松手 260ms 后 `flyToPose` 重新取景」的定时器。直接删除，改为**距离按半径等比缩放**
  （`ratio = 新半径/旧半径`），屏幕视角大小完全不变 → 零跳变。

### 3. 俯视 / 侧视按钮失效

根因：`setViewDir()` 先调 `flyToPose()`（内部设 `camMode='fly'`、`controls.enabled=false`），
紧接着又写 `camMode='idle'; follow=false; endFly();` —— 飞行在第一帧就被取消。

修复：删除那三行，只让 `flyToPose` 接管，到位时由 `updateCamera` 统一调 `endFly()`。

### 4. 地月距离修正

见上面 ②。默认滑块下月轨 = 8.1 倍地球半径（真实 60.3 倍在压缩场景里会跑到 143 单位，
超过地球日心距 100）。开「月球真实距离」时仍是 1:1（59.0× 地球半径）。

### 5. 地球按地球仪图案绘制

原来用 fbm 噪声当陆地，形状是随机斑点，认不出是地球仪。改为**按经纬度多边形填充**：

- `CONTINENTS`：24 块真实大陆/岛屿轮廓，共 368 个经纬度顶点
  （非洲/欧洲/西伯利亚/中国/印度/阿拉伯/中东/东南亚/印尼/日本/菲律宾/
   北美/南美/澳大利亚/塔斯马尼亚/新西兰/格陵兰/南极洲/马达加斯加/冰岛/不列颠/古巴/斯里兰卡）
- **必须用 canvas path fill 光栅化，不能逐像素点在多边形内** ——
  28 洲 × 30 顶点 × 52 万像素 ≈ 4 亿次运算会卡死主线程
- 投影公式 `x=(lon+180)/360·W`、`y=(90-lat)/180·H`，正好对应球面 UV 展开
- 海洋深度分档（深海/大陆架/浅海）+ 陆地按纬度分带（极地冰盖/苔原/针叶林/温带/
  副热带荒漠/草原/季风/赤道雨林）+ 海岸线浅色描边 + 15° 经纬网 + 差异化极冠
- 夜面城市灯光改成 **47 个真实经纬度城市**，严格裁剪在 `LANDMASK` 内
- **云层必须压薄**：它是贴在球外 1.012 倍的一层，`opacity: 0.88` 时截图里
  大陆被完全糊成白斑（等于「按地球仪绘制」白做）。改 `0.55`，
  噪声阈值同时从 `0.50-0.15*band` 抬到 `0.60-0.11*band`。

### 6. 悬停光圈移除 / 大气层强化

**光圈移除**：无论怎么调都容易被误读成大气层（`AdditiveBlending` +
早期 `depthTest:false` 会无视遮挡），且与真正的 `ATMOS` 大气壳无法区分。
现在 hover 只用纯 UI 反馈：标签 `.hl` 高亮 + 鼠标指针变化 + 右上角提示卡。
`haloTex` / `b.halo` 全部删除，`updateHalos()` 保留为空壳（主循环调用点不变，减少回归风险）。

**大气层强化**：`strength` 原本只有 0.30~0.42，在深空背景上几乎看不见。
整体上调（地球 1.60），并新增 `forward` 项模拟太阳在行星背后时的前向散射（迎日亮弧）：

```glsl
float fwd = pow(clamp(dot(V, -L)*0.5+0.5, 0.0, 1.0), 3.0);
float a = fres * uStrength * (0.22 + 0.78*lit + 0.55*uForward*fwd) * uOpacity;
```

水星不在 `ATMOS` 表里（现实中确实没有大气）。

### 7. 卫星系统 / 窄环

**卫星**：16 颗覆盖 5 颗行星，轨道半径用真实值（母星半径倍数）

| 行星 | 卫星 |
|---|---|
| 火星 | 火卫一 2.77、火卫二 6.92 |
| 木星 | 木卫一 5.90、木卫二 9.40、木卫三 14.97、木卫四 26.33 |
| 土星 | 土卫一 3.08、土卫二 3.97、土卫三 4.94、土卫四 6.65、土卫五 20.29、土卫八 59.0 |
| 天王星 | 天卫五 5.08、天卫三 9.76、天卫四 16.64 |
| 海王星 | 海卫一 14.39（**逆行**） |

实现要点：
- 卫星挂到 `b.grp`（不随自转的组）下的 `holder`，`holder.rotation.x = 母星倾角`。
  **挂到 `b.axis`（含自转）会跟着自转甩飞。**
- 显示半径统一按「母星半径 × `MOON_LOOK.s`」（真实比例在压缩场景里小到看不见）
- 轨道半径下限 `max(pr*m.R, pr*1.9)` 防被母星本体吞掉

**窄环**：天王星 8 条（ε 环系统，1.64~2.01 R）、海王星 4 条（1.69~2.56 R）。
窄环在 1024px 贴图上每条只有 ~28px 宽，`opacity` 低于 0.5 几乎看不见
（实测 0.34 时截图里只剩几条极淡的灰线，等于白加）→ 天王星提到 0.68、海王星提到 0.58。

**土星环投影阴影**：自定义 `ShaderMaterial`，把片元相对土星中心的位置投到垂直日方向的平面：

```glsl
vec3 rel = vW - uCenter;                    // ★ 必须减 uCenter
float s = dot(rel, uSunDir);                // 背阳侧
float d = length(rel - uSunDir*s);          // 到日轴距离
float inShadow = step(0.0, s) * (1.0 - step(uPlanetR, d));
float k = mix(1.0, uShadow, inShadow);
```

不减 `uCenter` 的话：土星在约 950 单位外，整条环带都会被判进阴影。

### 本轮踩的坑

1. **`g.ellipse()` 在等距柱状投影下画纬线会崩**。
   报 `Failed to execute 'ellipse': 7 arguments required, but only 6 present`，
   连带中断顶层脚本，`window.__solar` 整个 undefined。
   纬线在等距柱状投影下本来就是**水平直线**，正确写法是
   `g.moveTo(W/2-half, Y); g.lineTo(W/2+half, Y);`，`half = W/2*|cos(lat)|`；
   经线按 `cos(lat)` 横向收缩，极点自然收敛。
2. **`updateHalos(dt)` 的参数**：删掉光圈后函数体空了，签名仍是 `dt` 而调用点也传 `dt`，
   函数/调用不一致会让「声明顺序」类正则断言集体假失败。两边都清成无参。
3. **测试脚手架的切片范围**：`MOON_R` / `SUN_SIZE_REF` 定义在切片外，
   `_moonchk.js` / `_simtest.js` 会报 `ReferenceError: MOON_R is not defined`。
   凡是被 `syncMoonBoost` / `bodyRadius` 引用的常量都要在脚手架里补齐。
   另外 `bodyRadius` 手动复刻的版本必须跟源码同步（含太阳的 `SUN_SIZE_REF` 分支）。
4. **断言要跟着代码走，不要抄一份**。例如「辉光面积跨度」如果写死
   `baseK=17.14`，一改 `bodyRadius` 的压缩方式就集体报假失败。
   改为从源码正则解析真实数值再复算。
5. **注释里留着旧代码会被误判**：`r<0.6?16` 删掉后仍在注释里出现，
   断言要先 `replace(/\/\*[\s\S]*?\*\//g,'')` 剥注释再查。
6. **CDP 消息分发必须回传 id**：
   ```js
   if(o.id && waits.has(o.id)){ waits.get(o.id)(o); waits.delete(o.id); }
   ```
   缺这一行时 `send()` 的 Promise 永不 resolve，调试脚本表现为「无输出 + SIGTERM」。
7. **云层 opacity 与地球仪是矛盾的**：压薄云层后陆地清晰，但要注意别把
   `opacity` 降到让地球看起来像裸球 —— 0.55 是「有云感 + 看得见大陆」的平衡点。
